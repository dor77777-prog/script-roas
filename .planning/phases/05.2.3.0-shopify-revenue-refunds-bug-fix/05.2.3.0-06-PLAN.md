<objective>
Per D-D2, the operator needs a one-click way to retroactively re-attribute up to 20 days of cross-day refunds per store. This handles edge cases the 15-min rolling 3-day backfill (Plan 05) cannot reach — refunds processed >48h after the order was created (rare but real, e.g. for delayed PayPal refunds or operator-initiated bulk refunds against historical orders).

Three SEPARATE menu items (one per store) is deliberate per D-D2 — the operator runs them one at a time with a wait between clicks, to avoid concurrent Apps Script executions exceeding the 30 concurrent-execution quota. Each click runs `backfillRangeForStores(D-19, D, [storeId])` which iterates 20 days × 1 store = 20 per-store-day runs at ~15s each = ~300s ≈ 5 minutes — within the 6-min cap with a small safety margin.

The Hebrew wording is VERBATIM from D-D2 (not paraphrased) — this lets the user manual reference the exact string and the operator finds the menu item by direct text match.

Output: 3 menu items + 3 handler functions in Main.gs.
</objective>
