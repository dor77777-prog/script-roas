## Algorithm Summary

`getShopifyRefundsForDay_(storeId, dateStr)`:

1. Fetches `orders.json` with `updated_at_min/max` covering Asia/Jerusalem day D, paginating via Link headers up to a 50-page safety cap.
2. For each order, skips `test === true` and `financial_status === 'voided'`.
3. For each surviving order's `refunds[]`, applies the D-A2 cross-day filter:
   - `processedDay === dateStr` (refund happened on D) AND
   - `orderCreatedDay !== dateStr` (the order was NOT created on D — same-day refunds are already netted by `current_total_price`).
4. For each qualifying refund's `refund_line_items[]`:
   - Parses `parseFloat(rli.subtotal || rli.total || 0)` (fallback is dead code per PROBE-EVIDENCE.md §Finding 2 but kept for safety).
   - Accumulates into `storeRefundCad` (every item, including custom items with no product_id).
   - If `product_id` is a non-empty string, also accumulates into `byProduct[pid].refundCad`.
   - Otherwise, accumulates into `customItemRefundCad` (D-C3 invariant 3 diagnostic).
5. Bumps `processedAtCount` once per qualifying refund (not per line item).
6. Returns `{ storeRefundCad, byProduct, customItemRefundCad, processedAtCount }`.

Reconciliation invariant by construction: `storeRefundCad === Σ byProduct[pid].refundCad + customItemRefundCad` exactly (every line item dispatches into exactly one path). Logged at INFO if `customItemRefundCad > 0`, WARNING if `> 1 CAD`.

`previousDayStr_(dateStr, n)`:

Returns the YYYY-MM-DD string `n` days before `dateStr` (default `n=1`). Uses `Date.UTC(y, m-1, d-offset)` arithmetic so day-string math is DST- and month-boundary-safe (same convention as `nextDayStr_`). The `offset` guard collapses non-positive / non-finite / non-numeric `n` to `1`.
