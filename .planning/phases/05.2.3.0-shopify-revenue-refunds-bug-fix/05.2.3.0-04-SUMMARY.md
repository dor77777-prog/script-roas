## Deviations from Plan

### Stale plan body — algorithm mismatch (documented in contract_revision_notice)

The plan body (especially lines ~320–385 and ~460–580) was drafted against the PRE-2026-05-21 contract that referenced `transactions[].amount` as the store-level deduction and a `{ ..., totalTaxRefundedCad, shippingRefundedCad }` return type. The `<contract_revision_notice>` block at the top of the plan (and the rewritten `<objective>`) explicitly instructs the executor to treat the REVISED CONTEXT.md as authoritative and override the stale inline samples.

**Followed the revised contract throughout:**
- Return type: `{ storeNetCad, byProduct, customItemRefundCad }` (revised), not the stale `{ ..., totalTaxRefundedCad, shippingRefundedCad }`.
- Store-level deduction field: `refund_line_items[].subtotal` (revised), not `transactions[].amount`.
- 4 invariant tests cite the REVISED wording, not the stale wording (in particular invariant 3 uses cross-path reconciliation with `customItemRefundCad`, NOT the tax+shipping gap formulation).
- Fixtures include the `transactions[].amount` values from the probe (149.00 / 149.00 / 302.10) as "diagnostic noise" — they exist in the fixture only to assert that the algorithm correctly IGNORES them.

This is the contract-revision-notice's explicit deviation budget — not a freelance change.

### Additional fixture vs. test naming variance

The plan body's must_haves spec for invariant 3 read: `"(3) cross-path reconciliation 'storeNet == ΣbyProduct + customItemRefundCad' (no tax/shipping gap)"`. CONTEXT.md's REVISED D-C3 invariant 3 phrases this differently: `"storeRefundDeduction = Σ per-product[pid].refundCad + customItemRefundCad"`. The two formulations are algebraically equivalent given that byProduct.netRevenueCad = sameDayPerPidGross − perPidRefund (i.e., refundCad = sameDayPerPidGross − byProduct.netRevenueCad). The test for invariant 3 uses the CONTEXT.md formulation (which is the canonical source-of-truth per the contract_revision_notice) and includes the test comment to document the algebraic identity. This is consistent with both readings.
