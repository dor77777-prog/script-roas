## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing critical functionality] Replaced outdated `transactions[].amount` references with the REVISED `refund_line_items[].subtotal` contract**

- **Found during:** Task 1, while replacing the `__REPLACE_FROM_PROBE_AMOUNT__` placeholder.
- **Issue:** The plan's action body draft template referenced `refund.transactions[0].amount = __REPLACE_FROM_PROBE__ CAD` as the canonical "deduction" field shown to the operator. This contradicts the REVISED 2026-05-21 contract (PROBE-EVIDENCE.md §Finding 1) which empirically falsified `transactions[].amount` on 3/3 stores and switched the deduction to `refund_line_items[].subtotal`. The executor prompt's `<contract_revision_notice>` block explicitly states: **"Do NOT describe `transactions[].amount` as the deduction source"**.
- **Fix:** Replaced the line `Shopify רשם refund.processed_at = … עם refund.transactions[0].amount = … CAD` with `Shopify רשם refund.processed_at = 2026-05-20T15:27:19+03:00 עם refund.refund_line_items[0].subtotal = 68.80 CAD`. Also added a dedicated paragraph in §16.11.1 explaining why `transactions[].amount` is NOT used (2-4× the order total in practice due to currency mismatch + duplicate-refund artifacts). The "deduction" row in the dashboard before/after table now shows `−68.80` (the subtotal value, in order display currency), not the falsified `149` transactions value.
- **Files modified:** `docs/ROAS-Dashboard-User-Manual.md` (single insertion, no prior content overwritten).
- **Commit:** `dd6ff58`.

**2. [Rule 2 — Missing critical functionality] Added §16.11.4 documenting the probe diagnostic menu item**

- **Found during:** Task 1, cross-referencing the executor prompt's `<contract_revision_notice>` block.
- **Issue:** The prompt's operator-facing-semantics list includes: **"Probe diagnostic: `בדיקת חוזה החזרים (Shopify probe)` ROAS menu item runs the read-only `probeRefundContract()` function (Wave 1 — kept for operator diagnosis)."** The plan template's 5 sub-sub-sections (model / canonical example / cleanup menu / negative-revenue / verification URLs) did not include this diagnostic surface — but it's part of the operator-facing UI delivered by the phase, and omitting it would leave the operator unaware of the diagnostic exists.
- **Fix:** Added a new §16.11.4 (3 lines) describing the probe menu item, its read-only nature, when to use it, and where to find the output. Renumbered the original §16.11.4 (negative-revenue) → §16.11.5 and §16.11.5 (verification URLs) → §16.11.6.
- **Files modified:** `docs/ROAS-Dashboard-User-Manual.md`.
- **Commit:** `dd6ff58`.

**3. [Rule 2 — Missing critical functionality] Added a Net sales vs Gross sales clarification in §16.11.6**

- **Found during:** Task 1, while writing the verification-URL section.
- **Issue:** The revised D-C1 contract subtracts merchandise-only subtotal (not gross-of-tax-and-shipping). An operator comparing `data-daily` against Shopify Admin > Reports > Total Sales would see spurious diffs if they pick the wrong column (Gross sales vs Net sales vs Total sales with tax). Without explicit guidance, the operator might think the cross-check failed when in fact they're comparing wrong fields.
- **Fix:** Added a final note in §16.11.6 explaining that the cross-check should use Shopify's **Net sales** column (not Gross sales, not Total sales with tax). This matches the merchandise-net semantic of the revised contract.
- **Files modified:** `docs/ROAS-Dashboard-User-Manual.md`.
- **Commit:** `dd6ff58`.
