## Decisions Made

- **Loop bounds n=2..0** (exactly 3 iterations: D-2, D-1, D) — oldest-first per D-D1's rationale. This means a mid-execution Apps Script timeout leaves the older days correctly written and the most-recent day stale (which the NEXT 15-min trigger run will refresh), rather than leaving the older days uncorrected (which is the worse failure mode).
- **`runLiveUpdate` manual entry calls `runUpdateForDate` (multi-store), not `runUpdateForSingleStore_` (per-store)** — preserves the manual path's editor-user intent of "all 3 stores in one go", which is what `runLiveUpdate` always meant.
- **JSDoc emphasis casing** — the plan's verification gate `grep -q 'rolling 3-day backfill'` is case-sensitive. The action body proposed `ROLLING 3-DAY BACKFILL` (uppercase emphasis); I lowercased the one line to `rolling 3-day backfill` so the gate fires. Semantic content is identical; only emphasis differs. (See Deviations §1 below.)
- **`refreshAllStoresNow` deliberately left untouched** — that helper (DailyUpdate.gs:100) uses one-shot triggers that chain to the per-store wrappers, so it automatically picks up the new rolling behavior without any change to its own body. Per the plan's Task 1 "Rules" block.
