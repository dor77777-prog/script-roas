<contract_revision_notice>
This is a MODEL CHANGE, not a patch. The Wave-1 algorithm (current_total_price + cross-day filter) is replaced wholesale with the Wave-2 algorithm (total_price + every refund attributes to its processed_at day). The 4 critical findings from REVIEW.md collapse into a single coherent fix:

- **CR-01:** Switch `getShopifyRevenue` from `current_total_price` to `total_price` AND drop the cross-day filter in `getShopifyRefundsForDay_`.
- **CR-02:** Add `processed_at`-day filter to `getShopifyProductSalesForDay`'s `refundByLineId` map.
- **CR-03:** Remove `Math.max(0, ...)` clamp in `getShopifyProductSalesForDay`.
- **CR-04 / Gap 4:** TS mirror updated atomically in the same plan; KEEP-IN-SYNC docstring enumerates the 3 invariants.
- **WR-04 / Gap 6:** `updateStoreForDate_` refactored to call `getShopifyRefundsForDay_` ONCE and pass the result to both consumers via a new optional parameter (backward-compatible).

The model swap has these properties:
- `total_price` is immutable per Shopify Admin REST 2024-10 (confirmed by PROBE-EVIDENCE.md — the value is fixed at order creation regardless of subsequent refunds).
- Every refund attributes to ONE day — the day it was processed. Same-day refunds are no longer "absorbed" by `current_total_price` because we no longer use `current_total_price`; instead, the order's day shows the full gross (`total_price`) and the refund deducts on the day it was processed.
- Re-fetching prior-day rows is now safe: `total_price` is immutable, and refund deductions are stored on the refund-day row (not the order-day row).

Worked example (uzoshop probe data):
- Order 10803404276006: `total_price = 68.80` (immutable), refund processed `2026-05-20` with `refund_line_items[0].subtotal = 68.80`.
- 2026-05-02 row: shows +68.80 (gross, immutable).
- 2026-05-20 row: shows −68.80 (refund deduction on its processed_at day).
- Period sum: 68.80 − 68.80 = 0.00 (correct; net revenue is zero for fully-refunded orders).
- Under OLD algorithm: 2026-05-02 row showed +68.80 initially, then +0.00 after 20-day cleanup re-fetch (because `current_total_price` had dropped to 0); 2026-05-20 row showed −68.80 (cross-day deduction). Period sum: 0.00 − 68.80 = −68.80 (off by 68.80 — the double-deduction bug).
</contract_revision_notice>

```ts
export function computeRevenueWithCrossDayRefunds(
  orders: ShopifyOrderInput[],
  dateStr: string,
  tz: string = 'Asia/Jerusalem',
): CrossDayRefundResult {
  let sameDayGross = 0;
  let storeRefundDeduction = 0;
  let customItemRefundCad = 0;
  // Object.create(null) avoids prototype-key collisions (IN5-05 convention).
  const byProduct: Record<string, { netRevenueCad: number }> = Object.create(null);

  function bumpByProduct(pid: string, delta: number): void {
    if (!pid) return; // null/empty pid → caller handles via customItemRefundCad
    if (!byProduct[pid]) byProduct[pid] = { netRevenueCad: 0 };
    byProduct[pid].netRevenueCad += delta;
  }

  for (const o of orders) {
    // D-A1 / D-D4: exclude test and voided orders uniformly.
    if (o.test === true) continue;
    if (o.financial_status === 'voided') continue;

    const orderCreatedDay = dayInTz(o.created_at, tz);

    // === Same-day order path ===
    // gap-closure 08: gross uses total_price (immutable), NOT current_total_price.
    if (orderCreatedDay === dateStr) {
      // Invariant 1: total_price is immutable gross.
      sameDayGross += parseNum(o.total_price);

      // Per-product line gross = Σ price × quantity. (Line-level discounts
      // are not present in the narrow type — they're folded into the
      // intra-order refund_line_items.subtotal in practice for the
      // probe fixtures. Match this to Apps Script:
      //   line_gross = qty * price  (no total_discount visible in TS shape)
      //   line_net   = line_gross - intra_order_refund_subtotal
      // Apps Script subtracts line_discount AND refund_subtotal — when
      // line_discount is not modeled in TS, the test fixtures provide
      // current_total_price that already nets discounts, and per-product
      // net = line_gross - intra_order_refund.)
      const lineItems = o.line_items ?? [];
      for (const li of lineItems) {
        const pid = normalizeProductId(li.product_id);
        if (!pid) continue;
        const lineGross = parseNum(li.price) * (parseNum(li.quantity) || 0);
        bumpByProduct(pid, lineGross);
      }

      // Invariant 3: intra-order refundByLineId filtered to processed_at == dateStr.
      // A future-day refund on a same-day order must NOT deduct from same-day
      // per-product net — it deducts on its processed_at day via the
      // refund-day attribution loop below.
      const sameDayRefunds = o.refunds ?? [];
      for (const r of sameDayRefunds) {
        if (!r.processed_at) continue;
        const processedDay = dayInTz(r.processed_at, tz);
        if (processedDay !== dateStr) continue;
        const rlis = r.refund_line_items ?? [];
        for (const rli of rlis) {
          const pid = normalizeProductId(rli.product_id);
          if (!pid) continue;
          const amt = parseNum(rli.subtotal);
          bumpByProduct(pid, -amt);
        }
      }
    }

    // === Refund-day attribution path (gap-closure 08 model change) ===
    // Invariant 2: EVERY refund processed on day D deducts here. No cross-day
    // filter. Same-day refunds previously absorbed by current_total_price now
    // deduct here because the gross above uses total_price (immutable).
    const refunds = o.refunds ?? [];
    for (const r of refunds) {
      if (!r.processed_at) continue;
      const processedDay = dayInTz(r.processed_at, tz);
      if (processedDay !== dateStr) continue;  // refund must be on D
      // Note: NO `orderCreatedDay === dateStr` short-circuit anymore.
      // Same-day refunds count too.

      // D-C1 / D-C2: BOTH paths use refund_line_items[].subtotal.
      // transactions[].amount is intentionally IGNORED.
      const rlis = r.refund_line_items ?? [];
      for (const rli of rlis) {
        const amt = parseNum(
          rli.subtotal !== undefined && rli.subtotal !== null
            ? rli.subtotal
            : (rli.total ?? 0),
        );
        const pid = normalizeProductId(rli.product_id);
        storeRefundDeduction += amt;
        if (pid) {
          bumpByProduct(pid, -amt);
        } else {
          customItemRefundCad += amt;
        }
      }
    }
  }

  // D-D3: no clamping. Negative storeNet is legitimate.
  const storeNetCad = sameDayGross - storeRefundDeduction;

  return { storeNetCad, byProduct, customItemRefundCad };
}
```
