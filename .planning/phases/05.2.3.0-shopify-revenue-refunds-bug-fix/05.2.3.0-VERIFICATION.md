# Phase 05.2.3.0: Shopify Revenue Refunds Bug Fix — Verification Report

**Phase Goal:** Eliminate the load-bearing data-integrity bug where store-level and per-product Shopify revenue did not reflect refunds processed on a different day than the original order ("cross-day refunds"). After this phase a refund processed today on yesterday's order MUST appear as a deduction in today's revenue row across every dashboard surface, without double-counting and without silently rewriting prior-day rows.

## Gaps

### Gap 1: CR-01 — Cross-day refund double-deducted when prior-day rows are re-fetched (BLOCKING)

**Severity:** critical
**Status:** failed
**Affected files:** `Shopify.gs:111-185` (`getShopifyRevenue`), `Shopify.gs:624-729` (`getShopifyRefundsForDay_`), `DailyUpdate.gs:96-116` (per-store live wrappers), `Main.gs:368-397` (`refreshRevenue20DaysImpl_`), `dashboard-web/src/lib/shopifyRevenueRefunds.ts:154-241`

**Root cause:** D-A1's premise ("`current_total_price` IS net of refunds applied to the order") is true but stronger than D-A2 assumes. `current_total_price` reflects **every** refund on the order — including refunds processed on later days — not just same-day refunds. So when the rolling 3-day backfill re-fetches D-1 / D-2, or the 20-day cleanup re-fetches the full window, the order's day row silently drops by the cross-day refund amount, while `getShopifyRefundsForDay_` independently subtracts the same refund from the refund-day row. Net effect: every cross-day refund within 48h is double-deducted in normal operation.

**Required model change (chosen per orchestrator/operator decision 2026-05-21):**

Switch from `current_total_price` (a live, refund-reflecting field) to `total_price` (immutable, gross) for the order's day. Drop the cross-day filter — every refund deducts from its `processed_at` day. This:
- Makes re-fetching prior-day rows safe (`total_price` does not change).
- Preserves cross-day attribution (refund still appears on `processed_at` day).
- Keeps the rolling 3-day backfill + 20-day cleanup operational.
- Same-day refund case: order created D for $100, refunded D for $30 → row = `100 (total_price) - 30 (refund) = 70` (single, correct deduction).

**Acceptance criteria:**
- `getShopifyRevenue(storeId, dateStr)` sums `parseFloat(o.total_price || 0)` for orders created on dateStr (excl. test/voided), NOT `o.current_total_price`. Existing diagnostic log line updated to match.
- `getShopifyRefundsForDay_(storeId, dateStr)` drops the `orderCreatedDay === dateStr` short-circuit. Filter is now `processedDay === dateStr` only (every refund processed on day D attributes to day D, regardless of order's creation day).
- `dashboard-web/src/lib/shopifyRevenueRefunds.ts` mirrors both changes verbatim (KEEP-IN-SYNC).
- A new period-sum integration test is added to `dashboard-web/src/lib/__tests__/shopifyRevenueRefunds.test.ts` that fails BEFORE the fix and passes AFTER. (See Gap 5 for the test gap.)
- CONTEXT.md D-A1, D-A2, D-A3 revised with the new model; the historical reasoning is preserved (the rolled-back `current_total_price`-based attempt + the 2026-05-21 contract revision + the 2026-05-21 double-deduction finding).
- User Manual §16.11 updated; the false claim at `docs/ROAS-Dashboard-User-Manual.md:1512` ("שורת D-3 תישאר עם הסכום שהיה לפני ההחזר") is rewritten to match the new model.

**Root cause:** Same shape as CR-01 in the per-product path. The TS mirror filters intra-order refunds by `processedDay === dateStr` before deducting; Apps Script does not.

**Acceptance criteria:**

**NOTE:** After Gap 1's model change (`total_price` + drop cross-day filter), the per-product path also needs its own model change to use **`line_items[].price`-based gross at order day** + **refund_line_items at refund-processing day** (with no cross-day filter). The exact field choice should mirror the store-level pattern selected in Gap 1.

### Gap 3: CR-03 — `Math.max(0, …)` clamp on per-product net violates D-D3

- User Manual §16.11.5 either accurate after fix OR updated if a clamp is intentionally retained (in which case CONTEXT.md D-D3 needs amendment).
