<objective>
Every 15 minutes the live trigger fires, but currently each per-store wrapper only refreshes today (D). Cross-day refunds processed in the prior 48h (D-1, D-2) never get picked up unless the operator manually triggers a backfill. Per D-D1, the fix is a rolling 3-day backfill inside each per-store live wrapper — D-2, D-1, D in sequence. Estimated runtime is ~46s per wrapper (3x the existing ~15s per-store run), well under the 6-min Apps Script cap.

This plan ALSO updates the legacy `runLiveUpdate()` manual entry point (which calls `runUpdateForDate(todayStr_())`) to do the rolling 3-day backfill across all 3 stores. That preserves manual-editor parity with the trigger behavior — operators running `runLiveUpdate` from the editor get the same coverage as the scheduled triggers.

Output: 4 edited functions in DailyUpdate.gs.
</objective>
