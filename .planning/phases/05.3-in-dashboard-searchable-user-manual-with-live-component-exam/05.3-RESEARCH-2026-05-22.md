## 2. MDX pipeline decision: `next-mdx-remote-client@2.1.10`

| Lib | Bundle gz | Next 15 + RSC | React 19 | Active | Verdict |
|---|---|---|---|---|---|
| `next-mdx-remote@6.0.0` | ~12 KB + deps | yes (Turbopack workaround) | peer `react>=16` (loose) | **archived** | skip |
| `next-mdx-remote-client@2.1.10` | ~12 KB + deps | yes, RSC-first | peer `react>=19.1` ✓ | active | **PICK** |
| `@next/mdx@16.2.6` | build-only, 0 runtime | yes (first-party) | yes | active | skip — file-routed, would force splitting the manual into multiple `.mdx` files |
| custom unified+remark+rehype | ~80 KB if shipped to client | yes | yes | active | skip — DIY when an RSC-aware loader exists |

**Why `next-mdx-remote-client`:**
1. Officially endorsed by Next.js 15 docs.
2. Native RSC support (`/rsc` and `/csr` entry points).
3. Built-in `getFrontmatter()` utility for the footer.
4. ~50 KB total client gzip (compiler runs server-side, only the compiled output ships).
5. Peer dep `react>=19.1` matches us exactly.

### Live test I ran (in /tmp/fuse-hebrew-test)
```js
const fuse = new Fuse([
  { heading: 'מדריך', text: 'מדריך משתמש לדשבורד ROAS' },
  { heading: 'קמפיינים Campaigns', text: 'Pixel ו-Shopify לפעמים לא מסכימים' },
], { keys: ['heading','text'], threshold: 0.3, includeMatches: true });

fuse.search('מד');     // ✓ 1 hit → מדריך, indices [[1,1],[4,8]]
fuse.search('מדריך');  // ✓ 1 hit
fuse.search('ROAS');   // ✓ 2 hits
fuse.search('Pixel');  // ✓ 1 hit (Hebrew row + English term)
fuse.search('rias');   // ✗ 0 (threshold 0.3 too tight for transposed letters)
fuse.search('פיקסל');  // ✗ 0 (no Hebrew↔English transliteration — see §7-Q3)
```

CONTEXT.md §2 claimed Fuse "handles transliteration `rias` → `ROAS`". **Partially
wrong.** Fuse handles same-script edit-distance, not Hebrew↔English transliteration.
Acceptable for a single bilingual operator — see §7-Q3.

## 5. Risks + pitfalls specific to this codebase

### 5.1 CRITICAL — SWR cascades from `<HeroOverview>`

`HeroOverview.tsx:85-99` fires 2 unconditional `useSWR` calls for `/api/campaigns`
(current + previous range) on mount. If a mini-example imports `<HeroOverview>`,
those fetches hammer the API every time the manual tab opens.

**Mitigation:** Whitelist of safe imports for `manual-examples/`:
- `<KpiCards>` (pure)
- `<CampaignsTableRow>` (pure)
- `<MetaShopifyReconciliation>` (pure given reconciliation prop)
- `roasLabel` helper

**Blacklist:** `<HeroOverview>`, `<CampaignsTable>`, `<AdsDrawer>`, `<CampaignDrawer>`,
`<TodayLive>`, `<MonthlyTables>` — all fire SWR or read storage. Build the CPM chart
inline; never import the parent drawer.

### 5.2 Vitest include glob excludes `src/components/__tests__/**`

`vitest.config.ts:38-41` only matches `src/lib/**/__tests__/` + `src/inngest/**/__tests__/`.
The lone existing component test (`freshnessChip.test.ts`) currently does NOT run.

**Approach:** keep the search/highlight logic as pure functions in
`src/lib/manualSearch.ts` and test them under the existing `src/lib/__tests__/`
convention. No vitest config change needed.

### 5.3 Build memory — no issue

193 KB → MDX 3 compile on Vercel Hobby (4 GB build memory) is a non-event. Don't enable
`experimental.mdxRs: true` unless build time degrades (Rust compiler is still beta).

### 5.4 RTL must NOT flip ASCII diagrams or inline code

`<html dir="rtl">` in `app/layout.tsx:29` cascades into prose. UI-SPEC mandates two
required CSS additions:
```css
.roas-manual-prose pre { direction: ltr; text-align: left; }
.roas-manual-prose code, .roas-manual-prose pre { unicode-bidi: isolate; }
```
First render smoke test: `┌─┐` aligned, `?tab=manual` inline displays LTR (not
bidi-mirrored).

### 5.5 TOC hash anchors

The manual's TOC (l.65-94) uses `[heading](#anchor-slug)` hashes — `rehype-slug`
auto-generates ids matching GitHub's slugger. Verify on first render that all 33 TOC
links resolve. If slugs drift, swap in `github-slugger` explicitly.

### 5.6 Next.js 15 Turbopack workaround

If `next dev` switches to Turbopack in the future, `next-mdx-remote-client` may need
`transpilePackages: ['next-mdx-remote-client']` in `next.config.ts`. Production
Vercel builds use the regular compiler — unaffected.
