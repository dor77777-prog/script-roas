## Pattern Assignments

### `package.json` (root) — config / npm manifest

**Analog:** `dashboard-web/package.json` (1-40)

**Shape pattern (full file, lines 1-40):**
```json
{
  "name": "roas-dashboard-web",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "next lint",
    "test": "vitest run --passWithNoTests",
    "test:watch": "vitest",
    "test:coverage": "vitest run --coverage"
  },
  "dependencies": { ... },
  "devDependencies": { ... }
}
```

**Patterns to copy:**
- `"private": true` (line 4) — repo is not published to npm registry
- `"scripts": { ... }` object shape (lines 5-13) — one entry per task verb
- Top-level keys: `name`, `version`, `private`, `scripts`, `devDependencies` — in that order
- No `dependencies` key needed for root (only dev tooling)
- semver caret pin for tooling (e.g., `"vitest": "^2.1.0"` line 38) → mirror with `"@google/clasp": "^2.4.2"` per D-14
- No `"main"`, no `"type": "module"` — match dashboard-web's omission to avoid Node ESM/CJS resolution surprises in clasp

**Patterns NOT to copy:**
- Do NOT include `next`, `react`, `vitest`, or any dashboard-web runtime deps (CONTEXT.md §`domain` — phase is root-only, no overlap with dashboard-web)
- Do NOT add a `"workspaces"` key — CONTEXT.md §`canonical_refs` "Phase 2 carry-forward" explicitly says "two separate lockfiles"; do not introduce npm workspaces

**Concrete target shape (from CONTEXT.md D-14, NOT from dashboard-web):**
```json
{
  "name": "roas-tracker-root",
  "private": true,
  "scripts": {
    "deploy:gs": "clasp push --force"
  },
  "devDependencies": {
    "@google/clasp": "^2.4.2"
  }
}
```

## Shared Patterns

### Hebrew RTL documentation convention
**Source:** `SETUP.md` (1-30), `SYSTEM_OVERVIEW.md` (95-116)
**Apply to:** All edits to `SETUP.md` and `SYSTEM_OVERVIEW.md`
**Pattern:** Hebrew prose, English technical identifiers preserved inline (no transliteration of `clasp`, `GitHub Actions`, `CLASPRC_JSON`, etc.). Use `**bold**` for emphasis on Hebrew words and inline-backtick for code/filenames.

### npm manifest minimalism
**Source:** `dashboard-web/package.json` (1-40)
**Apply to:** Root `package.json`
**Pattern:** Top-level keys in order `name → version → private → scripts → dependencies → devDependencies`. semver caret for all version pins. No comments (JSON doesn't support them anyway). No optional metadata (`description`, `author`, `license`, `repository`) — dashboard-web omits all of these, root should match.

### Gitignore minimalism
**Source:** `.gitignore` (1-4) and `dashboard-web/.gitignore` (1-11)
**Apply to:** Root `.gitignore` edit
**Pattern:** One pattern per line, no comments, no section headers, no trailing whitespace. Preserve existing entries unless explicitly being removed.
