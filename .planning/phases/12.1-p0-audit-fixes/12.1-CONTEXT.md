## Specific Ideas

### Fix-by-fix anchor (each from raw-returns)

**INN-10 — cronLive.ts retry idempotency** (`raw-returns/inngest_cronLive.json` INN-10):
- Move SELECT (lines 803-809) into a separate `step.run('select-prior-spend-...', ...)` BEFORE `persist-rolling-3day`.
- Inngest memoizes `step.run` results across retries — prior values become stable.
- Alternative: don't preserve via SELECT; pass `null` for failed platforms and let `persistDayForStore`'s own SELECT (line 361-369) do the preservation via no-spendOverride branch.
- Regression test: custom step stub simulating one retry. Mock: tick 1 writes `fb=100,ga=200,tt=50`. Tick 2 has Meta fetch fail (returns null), Google + TikTok succeed (300, 60). Pin first attempt + 1 retry: assert `fb_spend_cad === 100` (prior preserved), not the value retry would read from its own first-attempt write.

**INN-16 — eventBackfill systemic-failure abort** (`raw-returns/inngest_eventBackfill.json` INN-16 + `12-trycatch-sweep.md` CAT-29):
- Add `console.warn` inside the catch at `:225` so per-pair failure is visible in Inngest run logs.
- Add systemic-failure abort: if the first 3 consecutive pairs fail with the same error message, throw to let Inngest retry the whole event.
- Regression test: mock `runDailyForStore` to throw same `Error('RLS denied')` on every call. Drive 5-pair backfill. Assert handler throws after ≤3 attempts with `Error: systemic failure (3 consecutive identical errors): RLS denied`. Assert pair indices 4-5 never invoked.

**INN-01 — cronDaily return-roas equivalence** (`raw-returns/inngest_cronDaily.json` INN-01):
- Build the return value at lines 1121-1126 from `dataDailyUpsertedRow.totalSpend` (the persisted value, which includes TikTok) instead of `merged.totalSpendCad` (which excludes TikTok).
- Regression test: set `tiktokSpendResult.spend > 0`; assert `result.roas === dataDailyUpsertedRow.roas` (within FP epsilon).

**ALG-04 + ALG-05 + ALG-06 — aiReport storeId-scoped keys** (`raw-returns/lib_algorithm_aiReport.json`):
- `lib/campaignsAggregator.ts`: thread `storeId` through the `Aggregated` type → composite key `${storeId}::${platform}::${campaignId}` (was `${platform}::${campaignId}`).
- `lib/aiReport.ts`: every map (`statusByCampaign`, `ordersByCampaignId`, `ordersByCampaignName`, suffix-match lookups) becomes storeId-scoped.
- Downstream consumers (CampaignsTable, CampaignsTableRow, ProductCentricView, multiMappingCohort, productCentricView, useCampaignTrueRevenue, campaignHealthScore): accept new key shape. Most are zero-mod (they use the type only for storage; the key string is opaque). The `aiReport` callers ARE the issue.
- Regression test: golden fixture with two stores (`zolplus` + `uzoshop`) sharing `campaignId='c1'` + `campaignName='Brand'` + `ttSpend>0`. Snapshot full markdown output. Assert each store's Currently-Off section receives only its own data. (`12-tests-needed.md` TG-02.)

**MMC-BLOCKER-01 — multiMappingCohort ranking** (`raw-returns/lib_algorithm_multiMappingCohort.json`):
- Explicit tie-break on `rankingScore` (current is composite-key sort; the under-shrinkage edge can reverse adjacent members).
- NaN/Infinity guard on input ROAS maps (current sort comparator is non-deterministic with non-finite values).
- Regression test: 5 cases including extreme-value (`roasShopifyPlatform>1000`) ranking pin (TG-05), reference-identity (`result.current === result.rankedAll[currentRank - 1]`), `others` array sort order, NaN guard, tie-break stability.

**ProductCentricView ALG-01 — sum-conservation** (`raw-returns/lib_algorithm_productCentricView.json`):
- Per-member `allocatedRevenueEstimate` must sum to `byPlatform.intraAllocatedRevenue` (currently 500 per platform but members sum to less).
- Likely: the allocator drops stale-mapped or dormant members from the denominator without removing them from the numerator. Fix: align numerator + denominator.
- Regression test: zero-spend cohort with 2 members + `intraAllocatedRevenue=500`. Assert `members.reduce((s,m) => s + m.allocatedRevenueEstimate, 0) === 500` within FP epsilon. Plus 3 other fixtures per `12-tests-needed.md` HP-21.
