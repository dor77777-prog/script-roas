<decisions>
## Implementation Decisions

### D-01: Sub-plan split

Single sub-plan (12.3-01) covers all 8 fixes since:
- 6 fixes are on independent API routes (low coupling).
- 2 fixes (INN-05, ALG-03) are subsidiary checks (likely no-op after 12.1).

A 1-PLAN structure is simpler. The Planner has discretion to split if the route fixes accumulate too many independent tasks (split rule: if any single PLAN file exceeds 500 LOC of task XML).

### D-02: Evidence source per fix (locked, same as 12.1/12.2 D-02)

Every fix MUST cite its `raw-returns/<file>.json` evidence pack in `<read_first>` and `<action>` must use the `fix_sketch` field verbatim.

### D-03: TDD per fix (locked, same as 12.1/12.2 D-03)

Test first → red → fix → green → atomic commit. Verify via `git stash` revert → red.

### D-04: Commit policy (locked, same as 12.1/12.2 D-08)

- Per-fix atomic commits. NO `git add -A`.
- Commit format: `fix(<area>): <finding-id> <brief description> (Phase 12.3)`
- Co-Authored-By per project convention.
- API-37 + API-38 are documented together in raw-returns (same file, same lines) → composite commit OK.

### D-05: No scope creep (locked)

Do NOT touch P0 surface (already fixed in 12.1) or P1 surface (Phase 12.2).

### D-06: Verification gate (locked, same as 12.1/12.2 D-06)

- Each fix's regression test fails on `git stash`.
- `cd dashboard-web && npm test` → exit 0.
- `cd dashboard-web && npx tsc --noEmit` → exit 0.
- Target test count: 12.2-final-count + ~8-12 new tests.

### D-07: Subsidiary check verification (INN-05 + ALG-03)

The planner MUST first run a verification pass on INN-05 + ALG-03:
1. **INN-05** — check if 12.1.1's INN-10 fix (separate `step.run('select-prior-spend-...')`) already resolved the per-platform-preserve SELECT being inside `persist-rolling-3day`. If YES: document as "resolved by 12.1.1, no Phase 12.3 work needed" and skip.
2. **ALG-03** — check if 12.1.2's ALG-04/05/06 storeId-scoped keys already side-effect-fixed the `last-write-wins` issue (likely yes if iteration is now deterministic with storeId scoping). If YES: document as "resolved by 12.1.2" and skip. If NO (e.g. still unordered within a single store's data): apply explicit chronological sort.

Document the verification per finding in the SUMMARY.

### D-08: API-37/38 + URL-obscurity context (operator awareness)

The operator-only routes are intentionally less-sanitized today (URL-obscurity trust). The Phase 12.3 fix is forward-looking — if/when the trust model changes (auth, multi-user, audit log), these become real CVEs. For now, the fix is:
- `userFacingError(err.message)` instead of raw `err.message`.
- Test asserts the response body does NOT contain raw Supabase strings like "RLS denied for user" or "duplicate key value violates unique constraint".

<specifics>
## Specific Ideas

- **API-10:** Remove `tokenPrefix` field entirely from debug response. Test asserts response body does NOT contain `tokenPrefix` key.
- **API-18:** Replace custom `htmlEscape` with `encodeURIComponent`-style attribute-context-safe escaping, OR add backslash + tab + newline coverage. Test injects `\\</script>` payload, asserts it doesn't break out.
- **API-23:** Wrap Inngest REST calls in `Promise.all` with `Promise.allSettled` for graceful per-event failures. Test asserts 50-event fan-out takes <2s (vs ~10s sequential baseline).
- **API-26:** Replace `parseFloat(spend)` with `Number(spend)` + `Number.isFinite` check. Test asserts `'1.5xyz'` → 400.
- **API-32:** Wrap per-table deletes in `Promise.all`. Test asserts total time <5s on 100k-row mocked tables.
- **API-37 + API-38:** Wrap response bodies in `userFacingError(err.message)`. Test stubs Supabase to throw `Error('RLS denied for table token_failures')`, asserts response body contains generic `"server error"` not `"RLS denied"`.
- **INN-05:** Subsidiary — likely already fixed by 12.1.1 INN-10. Verify + document.
- **ALG-03:** Subsidiary — likely already fixed by 12.1.2 ALG-04/05/06 storeId scoping. Verify + apply explicit chronological sort if not.
