## Decisions Made

See `key-decisions` in frontmatter. Summary:

- **Stub-with-_TODO over real Sheets capture**: worktree had no Sheets API credentials. Stub keeps the test scaffold load-bearing for CI and provides an explicit operator handoff signal in the active "stub-detection" warning test.
- **Tolerance: ±5% OR ±1 CAD (whichever wider)**: covers Phase 05.2.3.0 refund-correction delta + Meta/Google API version bumps (v20→v23/v24) + FX rounding noise. Narrower would cause Phase 05.2.3.0-delta false positives; wider would mask real drift.
- **All per-row assertions `it.skip` by default**: CI shouldn't consume production API quota on every PR (no-localhost memory rule + flake immunity + free-tier safety per Inngest+Frankfurter+Meta v23 quotas). Operator runs the non-skipped variant manually once.
- **Composite total-spend (#4) is the load-bearing parity check**: covers Meta + Google + manualOverrides end-to-end. Individual Meta/Google assertions (#2/#3) would fail on every day with a `manual_overrides` row (replace-semantics).

## Threat Surface Notes

Per the plan's `<threat_model>`:

- **T-05.6-21-T1 (Tampering — snapshot edited maliciously)**: ACCEPT. Git history + PR review are the mitigation. The snapshot diff is human-readable JSON; any edit shows in git diff with the full row-level delta. The stub's `_LOAD_BEARING` marker explicitly says "NEVER edit this JSON by hand" — the capture script is the only sanctioned write path.
- **T-05.6-21-D2 (DoS — CI hits production APIs every PR)**: MITIGATE. All 12 per-row assertions are `it.skip` by default. CI runs the 2 active scaffolding tests only; production API quota is untouched. Operator runs the full live suite manually with explicit intent.
- **T-05.6-21-T3 (Tampering — Shopify retroactively edits orders)**: ACCEPT. Sheets baseline is itself a snapshot; any retroactive Shopify edit affects BOTH the Sheets re-fetch AND the TS fetch consistently — the delta band stays the same. The CR-01/CR-02/CR-03 invariants in `shopifyRevenueRefunds.ts` are designed for this case (`total_price` is immutable, refunds attribute to `processed_at` only).

No new threat surface introduced — the test suite is read-only, hits no new endpoints, writes no new files at runtime (snapshot is committed; tests are runtime read-only). No new env vars consumed beyond what existing fetchers already use.
