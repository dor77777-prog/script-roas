    **Important caveat**: This test makes LIVE API calls (Shopify, Meta, Google, Frankfurter). It is SLOW. Mark each test as `it.skip` by default and document how to run them on-demand:

    ```typescript
    import { describe, it, expect } from 'vitest';
    import { readFileSync } from 'fs';
    import { fetchShopifyDayRows } from '../shopify';
    import { fetchMetaSpendForDay } from '../meta';
    // ... etc

    const snapshot = JSON.parse(readFileSync(
      __dirname + '/snapshots/sheets-baseline-2026-05-15-to-2026-05-20.json', 'utf8',
    ));

    /**
     * Algorithm-parity tests against frozen Sheets baseline (D-C4).
     *
     * RUN MANUALLY: `npx vitest run src/lib/fetchers/__tests__/algorithm-parity.test.ts --no-skip`
     *
     * These tests hit LIVE upstream APIs (Shopify, Meta, Google, Frankfurter) so
     * they are SLOW (~30s) and consume API quota. Default to `it.skip` so CI
     * doesn't run them on every PR.
     *
     * Expected delta: per Phase 05.2.3.0, Sheets old algorithm vs TS-port new
     * algorithm differs by the cross-day refund correction (CR-01 / CR-02 / CR-03).
     * If diff is OUTSIDE the documented delta, this test fails — algorithm has
     * drifted from intent.
     */
    describe('algorithm-parity (D-C4) — TS port vs Sheets baseline 2026-05-15..05-20', () => {
      for (const baseline of snapshot.rows) {
        const { date, storeId } = baseline;
        // Skip by default; run with --no-skip flag (or remove .skip in dev)
        it.skip(`Shopify revenue parity for ${storeId} ${date}`, async () => {
          const result = await fetchShopifyDayRows(storeId, date);
          // Allow ±5% delta or absolute ±1 CAD for the Phase 05.2.3.0 refund correction
          const delta = Math.abs(result.revenueCad - baseline.revenue);
          const pctDelta = baseline.revenue !== 0 ? delta / Math.abs(baseline.revenue) : 0;
          // Allow either small absolute OR small percentage — covers low-volume days
          expect(delta < 1 || pctDelta < 0.05).toBe(true);
        });

        // Similar skip-tagged blocks for Meta spend, Google spend, FX, manual_overrides merge.
        // The first launch should run these once manually + document the deltas in SUMMARY.
      }
    });
    ```

    For each fetcher, parameterize over the snapshot rows. Use `.skip` by default — the suite is a regression guard, not a CI gate (per "tests run against production APIs").

    The 5% tolerance band covers:
    - Phase 05.2.3.0 refund-correction delta (algorithm-by-design difference)
    - Meta API version bump (v20 → v23/24) — possible minor field shape adjustments
    - Google Ads API version bump (v20 → v24.1)
    - FX rounding noise

    If the delta exceeds 5% on any row, the test fails with a clear diff message including all 3 fetcher results vs the Sheets baseline. Operator inspects the diff in SUMMARY.

    NOTE: this is the most fragile plan — production-API-dependent tests are inherently flaky. Document this clearly in SUMMARY.
