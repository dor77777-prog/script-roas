## Validation matrix — what each route rejects

### `/api/operator/sync-now`

| Payload | Response | Why |
| ------- | -------- | --- |
| `{scope: 'all'}` | 202, `{accepted: 3, eventIds: [3 ids]}` | All-stores fan-out |
| `{scope: 'store', storeId: 'uzoshop'}` | 202, `{accepted: 1, eventIds: [1 id]}` | Single store |
| `{scope: 'store', storeId: 'foo'}` | 400, "Invalid payload..." | Allowlist reject |
| `{scope: 'foo'}` | 400, "Invalid payload..." | Bad scope |
| `{}` | 400, "Invalid payload..." | Missing scope |
| (network error in `inngest.send`) | 500, sanitised | userFacingError() |

### `/api/operator/backfill`

| Payload | Response | Why |
| ------- | -------- | --- |
| `{from: '2026-05-15', to: '2026-05-21', storeIds: ['uzoshop','zolplus']}` | 202, `{accepted: 1, eventIds: [1 id], range, storeIds}` | Valid |
| `{from: 'not-a-date', to: '2026-05-21', storeIds: ['uzoshop']}` | 400, "from and to must be YYYY-MM-DD strings" | Regex shape fail |
| `{from: '2024-12-01', to: '2026-05-21', storeIds: ['uzoshop']}` | 400, "from=… predates D-A3 history boundary 2026-05-01" | T-T1 mitigation |
| `{from: '2026-05-21', to: '2026-05-15', storeIds: ['uzoshop']}` | 400, "from > to" | Inverted range |
| `{from: '2026-05-15', to: '2026-05-21', storeIds: []}` | 400, "storeIds must be a non-empty array" | Empty |
| `{from: '2026-05-15', to: '2026-05-21', storeIds: ['evil']}` | 400, "Invalid storeId: evil" | T-T3 allowlist |

## HISTORY_BOUNDARY enforcement — three sites of truth

## Deviations from Plan

None substantive. The plan's `<action>` skeletons were followed essentially verbatim with these minor additive hardenings (well-within Rule 2 "auto-add missing critical functionality"):

1. **Added `typeof body.storeId === 'string'` guard** in sync-now route's `body.scope === 'store'` branch alongside the Set lookup. The plan's skeleton used `VALID_STORES.has(body.storeId)` directly; defending against `body.storeId === undefined` (which would coerce in a Set.has comparison) makes the validation explicit. No behavior change for valid payloads.

2. **Tightened backfill `invalid` check** to verify `typeof s !== 'string'` before `!VALID_STORES.has(s)`. Same defense — catches `storeIds: [null, 'uzoshop']` shape with a clean 400 instead of a coercion edge case.

3. **Used `setStoreIds((prev) => { ... })` functional updater** in BackfillPicker's `toggleStore` instead of mutating the captured `storeIds` closure. Idiomatic React; avoids a stale-closure bug if two toggles fire in the same tick (e.g., rapid keyboard navigation through checkboxes).

4. **Added `role="status"` / `role="alert"`** on the success/error `<p>` lines for screen-reader announcements. Matches the a11y pattern set by ManualOverridesCrud.tsx:288.

5. **Documented `lockfile drift in `deferred-items.md`** — see "Deferred Issues" below.
