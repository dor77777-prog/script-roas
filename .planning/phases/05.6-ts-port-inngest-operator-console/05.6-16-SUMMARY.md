## Deviations from Plan

### [Rule 3 — Blocking] Fixed pre-existing missing `BackfillPicker` import in page.tsx

- **Found during:** Task 1 (initial baseline tsc check)
- **Issue:** `dashboard-web/src/app/operator/page.tsx` referenced `<BackfillPicker />` as JSX on line 60 but did NOT import the symbol. Baseline `tsc --noEmit` failed with `error TS2304: Cannot find name 'BackfillPicker'` and `next build` would have failed at the type-check phase. Verified the regression was already present in the Plan 14 merge commit `9a23811` (the Plan 14 SUMMARY claims `tsc PASS`, but the merged tree does not contain the import statement — likely a worktree-merge mishap on the executor side).
- **Why blocking:** Plan 16's verify gate runs `tsc --noEmit && npm run build` against page.tsx (which this plan also modifies). Without the fix, my plan's verification could not pass.
- **Fix:** Added `import { BackfillPicker } from '@/components/operator/BackfillPicker';` alongside the existing imports. Single-line addition; no API or behavior change.
- **Files modified:** `dashboard-web/src/app/operator/page.tsx`
- **Commit:** included with Task 1's main commit

### [Editorial] Refreshed page.tsx docblock now that all 4 sub-sections are live

### Three minor style additions vs the plan's reference code

| Plan reference | What I shipped | Why |
|----------------|----------------|-----|
| `<button onClick=...>` | `<button type="button" onClick=...>` | Default `<button>` type is `submit`; in form contexts that triggers spurious form posts. Matches BackfillPicker.tsx:185. |
| `disabled:bg-gray-600` | `disabled:bg-gray-600 disabled:cursor-not-allowed` | UX consistency with BackfillPicker.tsx:187. |
| `<p>message</p>` | `<p role="status">message</p>` (and `role="alert"` for errors) | Screen-reader announcement parity with BackfillPicker.tsx:199-205. |

These do not change network behavior, payload shape, or visual layout in any way; they are pure quality matches to the existing operator-console component convention.
