## Decisions Made

1. **Frankfurter (not OXR) is the canonical FX source for the TS port.** The plan's `<critical_facts>` and earlier CONTEXT.md mentioned Open Exchange Rates, but `FX.gs:14` already uses `https://api.frankfurter.dev/v1/...`. The TS port matches the Apps Script source byte-for-byte (modulo cache layer). No OXR `app_id` env-var is needed and none was added.
2. **CacheService wrapper dropped.** `FX.gs:9-12,23` wraps the call in `CacheService.getScriptCache()` with a 21600s TTL. The TS port omits this because: (a) Frankfurter has no quota or rate-limit (per `https://frankfurter.dev/`); (b) Inngest step-level idempotency already prevents same-tick redundant calls; (c) our load profile is ~3 stores × 1 conversion/day + bursty backfill — well below any caching benefit threshold. If needed later, caching can move to the Inngest step layer (via `step.run` dedupe), keeping `fx.ts` pure.
3. **vitest glob widening lives in this plan's scope.** The original glob silently skips fetcher tests — that's a Rule 3 blocker for THIS plan, not a deferred cleanup. Fixed inline with a comment block that prevents regression.
4. **No REFACTOR commit.** The GREEN implementation is already minimal — 22 LOC, every line maps to a behaviour. No duplication to extract; no smell to address. The plan-level TDD gate sequence (`test → feat → refactor?`) is satisfied with just RED + GREEN per the executor's "refactor only if changes" rule.

## Note for Plan 04 (Meta fetcher)

Meta's Marketing API returns spend in the **account's currency**, which for our 3 stores is **ILS**. The Inngest daily/live cron functions must call `getFxRate('ILS', 'CAD', dateStr)` per day to convert before writing to `data_daily.spend` (which is stored in CAD per the Phase 05.5-01 schema). The fetcher is now available — plan 04 imports it via:

```typescript
import { getFxRate } from '@/lib/fetchers/fx';
```

For backfill: each day in the range needs its own `getFxRate(...)` call (FX rates are per-day). Frankfurter's weekend-shift behavior means Saturday/Sunday Meta spend rows convert at the Friday rate; this matches Apps Script's existing behavior exactly.
