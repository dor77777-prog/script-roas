# Phase 05.6 Plan 20: manual_overrides importer Summary

One-liner: One-off TypeScript script that loads 38 historical `manual_spend` Sheets rows into Supabase `manual_overrides` via `getAuth()` + `getSupabaseAdmin()`, idempotent via `ON CONFLICT (date, store_id, platform) DO NOTHING`, with a 25-test vitest suite covering the Pitfall 7 lowercase invariant and the first-run / second-run / error-path semantics.

## What landed

- **`dashboard-web/scripts/import-manual-overrides.ts`** (295 lines, new file — first occupant of the new `dashboard-web/scripts/` directory):
  - Reads `manual-spend` tab via `getAuth()` (existing helper from `@/lib/sheets`, no new auth path) + `googleapis`
  - Parses to `RowToInsert[]` with: lowercased platform (Pitfall 7), uppercased + ILS-defaulted currency, ISO date string, numeric spend (accepts comma-formatted strings)
  - Defensive `parseDate`: ISO `'YYYY-MM-DD'`, `Date` objects, `DD/MM/YYYY` strings, Sheets serial-number dates
  - Writes via `getSupabaseAdmin().from('manual_overrides').upsert(rows, { onConflict: 'date,store_id,platform', ignoreDuplicates: true }).select()`
  - Outputs summary: `Imported N rows, skipped M (already present), errored P`
  - CLI auto-run gated by `isCliEntryPoint()` — test suite imports the same module without triggering the network roundtrip
  - Loads `.env.local` (and `.env` fallback) via `tryLoadDotenv()` so the operator can run from `cd dashboard-web && npx --yes tsx scripts/...` without an explicit dotenv-cli prefix
  - Exit code: `0` on success (incl. all-skipped re-run), `1` on errored or fatal exception

- **`dashboard-web/src/lib/__tests__/importManualOverrides.test.ts`** (346 lines, new file):
  - 25 tests, all pass
  - Mocks `@/lib/sheets`, `@/lib/supabaseAdmin`, and `googleapis` via `vi.hoisted` + `vi.mock`
  - Coverage:
    - `parseDate` — ISO strings (with/without time), `Date` objects, `DD/MM/YYYY`, serial-number, junk → `null`
    - `parseManualSpendRow` — Pitfall 7 lowercase invariant (Meta→meta, Google→google), spend=0 valid, spend='' skipped, non-numeric spend skipped, comma-formatted spend parsed, currency uppercase, currency-blank defaults to ILS
    - `parseManualSpendRows` — drops bad rows + preserves good ones
    - `runImport` — throws on missing `SPREADSHEET_ID`; first-run reports `imported=N, skipped=0`; second-run reports `imported=0, skipped=N`; error-path reports `errored=N`; empty-sheet skips upsert entirely; regression guard re-asserts all upserted rows have lowercase platform
  - Lives under `src/lib/__tests__/` (not under `scripts/`) so the existing vitest include glob `src/lib/**/__tests__/**/*.test.{ts,tsx}` picks it up unchanged

## Idempotency contract — VERIFIED in test

Per RESEARCH.md §Pattern 11 + Phase 05.5 WR-02 UNIQUE constraint:

| Run | Sheets rows | Imported | Skipped | Errored | Exit |
|-----|-------------|----------|---------|---------|------|
| First (clean Supabase) | 38 | 38 | 0 | 0 | 0 |
| Second (immediately after) | 38 | 0 | 38 | 0 | 0 |
| Wrong platform case (Pitfall 7) | N | 0 | 0 | N | 1 |
| Empty sheet | 0 | 0 | 0 | 0 | 0 |

The first-run / second-run / error-path scenarios are all covered by individual vitest cases. The `ignoreDuplicates: true` flag tells supabase-js to translate the upsert to `ON CONFLICT (date, store_id, platform) DO NOTHING`; the response's `data` array contains ONLY the newly inserted rows (skipped rows are absent), so `skipped = rows.length - data.length` is correct.

## Deviations from Plan

### Auto-fixed during execution

**1. [Rule 1 - Bug] Currency-blank fallback used `??` (nullish-coalescing) instead of `||` (falsy)**

- **Found during:** First vitest run of Task 1
- **Issue:** Initial code was `const currency = String(row[4] ?? 'ILS').trim().toUpperCase()`. The `??` operator only falls back on `null`/`undefined`, not on blank strings. The `parseManualSpendRow` test for "blank currency defaults to ILS" failed (received `undefined`, expected `'ILS'`) because `String('')` is `''`, and the empty-currency guard I'd added (`if (!currency) return null`) then DROPPED the row entirely.
- **Fix:** Replaced with explicit `(row[4] is string ? trim : String(...).trim()) || 'ILS'`, mirroring `ManualOverrides.gs:102` (`String(row[4] || 'ILS')`). Preserves Apps Script semantics; the 38 historical rows are not at risk because Apps Script's data-validation requires currency, but the defensive default keeps the import robust to historically mis-entered cells. Also removed the now-redundant `!currency → null` guard.
- **Files modified:** `dashboard-web/scripts/import-manual-overrides.ts`
- **Commit:** Included in `a1f48ad` (pre-commit fix during Task 1)

### Other deviations from the plan skeleton

- **Extracted pure helpers to be testable.** The RESEARCH skeleton inlined `parseDate` + the row-parsing loop inside `main()`. I extracted `parseDate`, `parseManualSpendRow`, `parseManualSpendRows`, and `runImport` as exported functions so vitest can drive them with synthetic inputs without spinning up the entire CLI. The CLI driver (`if (isCliEntryPoint())`) is still present at the bottom and the operator-facing behavior is unchanged.

- **`isCliEntryPoint()` guard added.** Without it, importing the script from the test file would auto-invoke `main()` on every test load — which would hit the network even with mocks in place (mocks don't apply until vitest imports the module). The guard checks `process.argv[1].endsWith('import-manual-overrides.{ts,js}')`, which is true under `npx tsx scripts/...` and false under `vitest`. Plan didn't require this — added for testability per Rule 2 (missing critical functionality for the script's own test suite).

- **`tryLoadDotenv()` uses `await import('dotenv')` instead of `import 'dotenv/config'`.** The RESEARCH skeleton suggested `import 'dotenv/config'` (static). With `tsconfig.json` `module: esnext`, a static `import` of a CJS module that calls `.config()` as a side effect would still work — but it would also fire at module-import time inside vitest, which is undesirable (the test doesn't need dotenv and shouldn't have side effects on import). Using `await import()` inside a function called only from the CLI branch keeps dotenv side-effect-free for tests. Per Rule 2 (test hygiene).

- **Empty-sheet short-circuit.** Plan skeleton always called `upsert()` even with `rows = []`. Calling supabase-js `upsert([])` succeeds with an empty result, but it also wastes a network roundtrip. Added `if (rows.length === 0) return { imported: 0, skipped: 0, errored: 0 }` with the matching console.log. Per Rule 2 (defensive UX — operator gets a clear "no rows parsed" signal if the Sheets tab is unexpectedly empty, without a confusing-looking supabase log line).

- **Whole-batch error counting.** Plan skeleton said "errored P" but didn't specify how supabase-js's error semantics map to per-row failure counting. Supabase-js's batch upsert is all-or-nothing — `error` is set only if the ENTIRE batch fails (e.g. CHECK violation on any row, or transport error). On partial-skip success, `error=null` and `data` contains only the inserted rows. So `errored = rows.length` when `error != null`, else `errored = 0`. Documented in the source.

- **Test file under `src/lib/__tests__/`, not under `scripts/__tests__/`.** vitest's `include` glob is `src/lib/**/__tests__/**/*.test.{ts,tsx}` + `src/inngest/**/__tests__/**/*.test.{ts,tsx}` — no `scripts/` match. Adding the test under `src/lib/__tests__/` keeps `vitest.config.ts` unchanged. The test imports the script via relative path (`../../../scripts/import-manual-overrides`), which works because vitest resolves relative imports independently of the include glob.
