### S-1 — Lazy factory for server-only clients

**Source:** `dashboard-web/src/lib/supabase.ts:26-44`

**Apply to:** `supabaseAdmin.ts`, `inngest/client.ts`

```typescript
// Pattern (verbatim from supabase.ts:28-44):
let cached: SupabaseClient | null = null;

export function getSupabase(): SupabaseClient {
  if (cached) return cached;

  const url = process.env.SUPABASE_URL;
  const key = process.env.SUPABASE_ANON_KEY;

  if (!url || !key) {
    throw new Error('SUPABASE_URL or SUPABASE_ANON_KEY missing — check Vercel env vars');
  }

  cached = createClient(url, key, {
    auth: { persistSession: false },  // server-side, no user session
  });
  return cached;
}
```

**Why this exact shape (from `supabase.ts:20-25` docstring):** "the throw happens inside the function so a missing env var manifests as a caught `pingSupabase` rejection (→ amber SyncIndicator) instead of a route module that fails to load (→ HTTP 500 → indicator stays neutral / never amber, silently violating the soft-fail contract documented in the User Manual §2.1)."

**Conventions to copy:**
1. Module-level `let cached: SupabaseClient | null = null;` (NOT `const`)
2. `if (cached) return cached;` short-circuit on first line of factory
3. Throw inside the function with the exact error string `"X or Y missing — check Vercel env vars"`
4. `auth: { persistSession: false }` for server-side clients
5. Full JSDoc explaining why anon vs service_role (or why lazy vs module-load)

### S-2 — Route soft-fail with HTTP 200 + sanitized error + cacheControl

**Source:** `dashboard-web/src/app/api/dashboard-state/route.ts:23-56` (GET) and `dashboard-web/src/app/api/data/route.ts:60-86` (degraded path)

**Apply to:** `api/operator/jobs/route.ts`, `api/operator/manual-overrides/route.ts` (GET branch)

```typescript
// Pattern (verbatim from dashboard-state/route.ts:23-56):
export async function GET() {
  try {
    const data = await fetchDashboardState();
    return NextResponse.json(
      { kv: data.kv, updatedAtByKey: data.updatedAtByKey, lastUpdated: new Date().toISOString() },
      {
        headers: {
          'Cache-Control': cacheControl('dashboardState'),
        },
      },
    );
  } catch (err) {
    const message = err instanceof Error ? err.message : String(err);
    console.error('dashboard-state GET failed:', message);
    return NextResponse.json(
      {
        kv: {},
        updatedAtByKey: {},
        lastUpdated: new Date().toISOString(),
        error: userFacingError(message),
      },
      { status: 200 },
    );
  }
}
```

**Conventions to copy:**
1. `try { ... } catch (err) { ... }` at the top of every handler — never let errors bubble unhandled
2. `const message = err instanceof Error ? err.message : String(err);` (exact narrowing pattern — every existing route uses it)
3. `console.error('<route-name> failed:', message);` — log raw message server-side for ops
4. **Soft-fail with `status: 200`** + same response shape as success path (e.g., `kv: {}`, `rows: []`) + `error: userFacingError(message)` field — matches `data/route.ts:76-85`, `store-meta/route.ts:33`, `campaigns/route.ts:52-58`, `health/route.ts:90-93`
5. Use `cacheControl('<key>')` from `@/lib/cacheConfig` for the `Cache-Control` header. **Do not write the string by hand.** Adding a new route REQUIRES extending `CACHE_CONFIG` in `dashboard-web/src/lib/cacheConfig.ts:12-33`.
6. **DEGRADED path uses `'Cache-Control': 'no-store'`** (see `data/route.ts:84`) — prevents pinning an error response in the CDN for the full revalidate window. **Per WR-02 comment in `data/route.ts:73-76`.**
7. Sanitize the error with `userFacingError(message)` from `@/lib/apiErrors:17-34` before sending to client

### S-3 — Next.js route segment config: `revalidate` MUST be a literal

**Source:** `dashboard-web/src/app/api/data/route.ts:14`, `dashboard-state/route.ts:10`, `health/route.ts:24`, `store-meta/route.ts:10`, `campaigns/route.ts:9`

**Apply to:** all new GET routes under `api/operator/`

```typescript
// Pattern (verbatim from data/route.ts:14):
export const revalidate = 60; // matches CACHE_CONFIG.data.revalidate; literal required by Next.js static analysis
```

**Conventions to copy:**
1. **Literal number only** — `export const revalidate = CACHE_CONFIG.foo.revalidate;` FAILS Next.js's static analyzer with "Unsupported node type MemberExpression" (Phase 05.5-03 Deviation #1)
2. The trailing comment MUST exist and reference the matching `CACHE_CONFIG.<key>.revalidate` entry — this is what keeps the literal in sync with `cacheConfig.ts`
3. **NEVER both `revalidate` AND `dynamic = 'force-dynamic'`** — they conflict; `force-dynamic` overrides. See the dedicated comment in `data/route.ts:11-14` and `dashboard-state/route.ts:11-22`. Use `revalidate` for GET-only, `force-dynamic` for CRUD (e.g., manual-overrides POST/PATCH/DELETE).
4. For CRUD routes that must NEVER be cached, the existing convention in `cloudSync.ts` payloads uses `'Cache-Control': 'no-store'` per-response instead of `force-dynamic` — choose whichever the route's other handlers tolerate. RESEARCH.md Pattern 8 (`manual-overrides/route.ts`) uses `export const dynamic = 'force-dynamic';` — first occurrence in repo, flag in PLAN.

### S-4 — `userFacingError(message)` for every client-bound error string

**Source:** `dashboard-web/src/lib/apiErrors.ts:17-34`

**Apply to:** every `/api/operator/**/route.ts` and any error surface that the browser will display

```typescript
// Pattern (verbatim from apiErrors.ts:17-34):
export function userFacingError(message: string): string {
  if (/permission|forbidden|403/i.test(message)) {
    return 'הטעינה נכשלה: הרשאות אינן מספיקות.';
  }
  if (/not found|404|Unable to parse range/i.test(message)) {
    return 'הטעינה נכשלה: הגיליון לא נמצא.';
  }
  // ... etc
  return 'הטעינה נכשלה: שגיאה לא צפויה.';
}
```

**Conventions to copy:**
1. **Never leak raw `err.message` to the client.** Raw messages contain spreadsheet IDs, service-account emails, Inngest signing keys (in errors), etc. See CR-01 in `02-foundations/02-REVIEW.md` cited in `apiErrors.ts:13-16`.
2. **Extend `apiErrors.ts`** if the operator console surfaces new error patterns (e.g., Inngest API errors). Add new branches at the top of the function; the final `return` is the catch-all. Hebrew strings only — match the existing pattern's locale.

### S-7 — `parseNumber` / `parseDate` helpers (per-file private)

**Source:** `dashboard-web/src/lib/sheets.ts:77-103`, `dashboard-web/src/lib/campaigns.ts:65-69`, `dashboard-web/src/lib/ads.ts:59-68`, `dashboard-web/src/lib/shopifyRevenueRefunds.ts:135-148`

**Apply to:** every fetcher in `dashboard-web/src/lib/fetchers/*.ts` and `scripts/import-manual-overrides.ts`

**Conventions to copy:**
1. Define `parseNumber`/`parseDate` as **private file-scope functions**, NOT shared lib utilities. The codebase repeats them per-file rather than centralizing — this is intentional (each file controls its own input quirks).
2. **`parseNumber` shape** (verbatim from `sheets.ts:77-81`):
   ```typescript
   function parseNumber(v: unknown): number {
     if (v === null || v === undefined || v === '') return 0;
     const n = typeof v === 'number' ? v : parseFloat(String(v).replace(/,/g, ''));
     return Number.isFinite(n) ? n : 0;
   }
   ```
3. **`parseDate` shape** must accept Sheets serial-number values AND ISO strings AND `DD/MM/YYYY` strings (see `sheets.ts:83-103`). For Postgres-readers and Inngest functions, dates already come as `YYYY-MM-DD` strings, so a thinner `parseDate` is fine — but mirror the contract: `string | null` return, `null` on bad input.
4. **`Object.create(null)`** for maps that index by user-controllable keys (e.g., `manual_overrides` key `"storeId|platform|date"`). See `sheets.ts:357-358` ("Object.create(null) hardens against prototype pollution") and `shopifyRevenueRefunds.ts:159`.

### S-9 — SWR polling for client-side data

**Source:** `dashboard-web/src/components/SyncIndicator.tsx:26-44` + `dashboard-web/src/components/Dashboard.tsx:46-53,94-98`

**Apply to:** `components/operator/JobsTable.tsx` (15s polling per D-D3)

const fetcher = (url: string) => fetch(url).then(r => (r.ok ? r.json() : null));

const { data: health } = useSWR<HealthResponse | null>(
