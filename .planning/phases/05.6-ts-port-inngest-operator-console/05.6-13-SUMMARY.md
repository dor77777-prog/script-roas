## Decisions Made

- **Soft-fail HTTP 200 on every error path** mirrors `/api/dashboard-state` and avoids forcing the SWR client into a hard-error state. The `JobsTable` distinguishes three failure modes: hard SWR error (red text), `data.error` from the proxy (amber banner), and empty `runs[]` (neutral text). Each gets a distinct visual treatment so the operator can tell apart "request crashed" from "Inngest returned 401" from "Inngest is up but no functions are registered yet."
- **15s polling cadence (D-D3)** — `refreshInterval: 15_000` matches `cron-live`'s 15-min schedule so the operator sees the next scheduled run within at most one tick. Chose `useSWR` polling over `@inngest/realtime-react` to avoid wiring a second SDK for a once-a-day-glance surface.
- **24h `received_after` lookback** bounds the per-request fan-out cost (3 stores × 96 cron-live + 3 cron-daily = max 291 events/day, well under the `MAX_LIMIT=50` cap). Anything longer would warrant cursor-based pagination, which the v1 spec supports but the operator's "today's runs" mental model doesn't need.
- **N+1 fan-out** is unavoidable because Inngest REST v1 has no `/v1/runs?function_id=...` LIST endpoint (verified against the OpenAPI spec referenced in RESEARCH §Pattern 6). We list events first, then iterate. Per-event run-fetch failures are swallowed + logged so a single sick event doesn't blank the entire table.
- **Empty `runs[]` is the expected state** until Wave 9 deploys `/api/inngest` with registered Inngest functions. The component renders "אין ריצות אחרונות" + the `lastUpdated` pulse line so the operator can confirm polling is alive even with zero rows. NOT documented under "Known Stubs" because the proxy + UI are fully functional — they just have no upstream data yet, which is a Wave 9 dependency, not a stub.
- **dir="ltr" inside the RTL container** is deliberate on the duration cell and the expanded `<pre>` panel — JSON syntax and floating-point durations both read left-to-right even inside Hebrew text. Mirrors the existing `ManualOverridesCrud` cell-level `dir="ltr"` pattern.

## Deviations from Plan

None of the auto-fix rules fired. Two minor adjustments worth recording:

1. **Removed literal `force-dynamic` and `INNGEST_SIGNING_KEY` tokens from comment prose.** The plan's pre-merge greps are strict `grep -c` checks, not "match the env-var pattern outside string literals" — any literal occurrence (including comments) fails the gate. Initial draft had documentation comments explaining "we do NOT use `force-dynamic`" and "this file must never reference `INNGEST_SIGNING_KEY`"; both rephrased to omit the literal tokens while preserving the warning. Same intent, no false-positive on the gate.
2. **Worktree had no `node_modules`.** Symlinked `dashboard-web/node_modules` → parent repo's `node_modules` so `tsc` and `next build` could resolve dependencies (Next 15 + bundler module resolution requires the local `typescript@5`). The symlink is a working-tree artifact — not staged, not committed, and `.gitignore` already excludes `node_modules`.
