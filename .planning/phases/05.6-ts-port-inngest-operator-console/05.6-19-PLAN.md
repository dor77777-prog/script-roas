  <action>
    For each route, locate the line where a `sheets.ts` reader is called (typically `await fetchDailyData(...)` or similar). Add the conditional:

    Pattern (per RESEARCH §Pattern 6.5 lines 903-914):

    Before:
    ```typescript
    import { fetchDailyData } from '@/lib/sheets';
    // ...
    const rows = await fetchDailyData({ range });
    ```

    After:
    ```typescript
    import { fetchDailyData } from '@/lib/sheets';
    import { fetchDailyDataFromPostgres } from '@/lib/postgresReaders';
    import { readFrom } from '@/lib/featureFlags';
    // ...
    const rows = readFrom() === 'postgres'
      ? await fetchDailyDataFromPostgres({ range })
      : await fetchDailyData({ range });
    ```

    Repeat for each route's primary fetcher. Map:
    - `/api/data` → fetchDailyData ↔ fetchDailyDataFromPostgres
    - `/api/store-meta` → fetchStoreMeta ↔ fetchStoreMetaFromPostgres
    - `/api/dashboard-state` → fetchDashboardState ↔ fetchDashboardStateFromPostgres (GET only; POST writes stay on sheets in 05.6 — flag a TODO for 05.7 to add write-path branching)
    - `/api/products` → fetchProducts ↔ fetchProductsFromPostgres
    - `/api/campaigns` → fetchCampaigns ↔ fetchCampaignsFromPostgres
    - `/api/ads` → fetchAds ↔ fetchAdsFromPostgres
    - `/api/orders-attribution` → fetchOrdersAttribution ↔ fetchOrdersAttributionFromPostgres
    - `/api/product-catalog` → fetchProductCatalog ↔ fetchProductCatalogFromPostgres

    **CRITICAL:** Each change must preserve the soft-fail HTTP 200 pattern. The conditional goes INSIDE the existing try/catch; both branches throw on error → same catch handles it.

    **For routes where the function signature differs slightly between sheets and postgres** (e.g., extra opts), normalize at the call site — both should accept the same `opts` parameter.

    If a route calls multiple sheets readers in parallel (e.g., `Promise.all([fetchDailyData, fetchSomethingElse])`), wrap each in the same conditional.

    Verify the existing tests pass (don't break the Sheets default path).
  </action>
