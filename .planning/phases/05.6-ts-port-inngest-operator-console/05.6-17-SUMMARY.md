## Shape-parity invariants preserved

The cardinal invariant (D-E3) is that each reader's return value is structurally interchangeable with its Sheets twin. Every Sheets-side normalization was carried forward:

- **DailyRow derived fields** match `sheets.ts:fetchDailyData` exactly:
  - `totalSpend = total_spend_cad || (fbSpend + gaSpend)` when DB is null
  - `roas = revenue / totalSpend` when DB is null (0 when `totalSpend = 0`)
  - `grossProfit = revenue - totalSpend` when DB is null
  - `cogs = revenue * COGS_RATE_OF_REVENUE` (0.25) when DB is null
  - `netProfit = revenue - totalSpend - cogs` when DB is null
  - `hasCogs = true` always (matches sheets.ts)
- **StoreMetaRow normalizations** match `sheets.ts:275-276`:
  - `meta_ad_account_id` → `metaAdAccountId` with `act_` prefix stripped, or `null` if blank
  - `google_ads_customer_id` → `googleAdsCustomerId` with dashes stripped, or `null` if blank
  - `last_error` → `lastError` coerced to `null` when blank
- **DashboardState** uses `Object.create(null)` for `kv` and `updatedAtByKey` (prototype-pollution hardening matching `sheets.ts:357`); preserves last-updated dedup logic for forward-compatibility even though the PRIMARY KEY (key) prevents duplicates today.
- **CampaignRow / AdRow `platform`** TitleCased at the boundary: DB `'meta'`/`'google'` (lowercase, enforced by CHECK constraint in migration `20260521075741`) → `'Meta'`/`'Google'` matching the existing CampaignRow / AdRow type unions.
- **OrderAttribution `includeLineItems`** toggle preserved exactly: default `false` returns `lineItems: []` so iteration without null-guards keeps working (matches `ordersAttribution.ts:259`). Permissive `parseLineItems` mirrors the Sheets-side helper (drops malformed entries, never errors the whole row).
- **Empty-row filters** preserved verbatim:
  - products: `if (units <= 0 && revenue <= 0) continue`
  - campaigns/ads: `if (spend === 0 && impressions === 0 && conversions === 0) continue`
- **STORE_NAME_BY_ID** fallback for `campaigns_daily` / `ads_daily` / `orders_attribution` / `product_catalog` (none carry `store_name` in the schema). The mapping is the same canonical 3-store list used by `campaigns.ts:38` STORE_TAB_CONFIG.

**2. [Rule 2 - Type safety] supabase-js v2 GenericStringError narrowing**
- **Found during:** Task 2 `tsc --noEmit` run
- **Issue:** With supabase-js v2 and an untyped `Database` schema, `.from('t').select('cols').gte(...).lte(...)` returns `{ data: T[] | null, error: Error | null }` where `T = RowShape | GenericStringError`. TypeScript narrows row access against `GenericStringError` after the `error` check, producing 82 `Property X does not exist on type 'GenericStringError'` errors.
- **Fix:** Added a `DbRow = Record<string, unknown>` type alias and a single cast `(data as unknown as DbRow[] | null) ?? []` immediately after the post-error-check, so the rest of each function reads snake_case columns via index access. The cast is safe because the error path would have thrown already. Pattern documented inline in the file.
- **Files modified:** `dashboard-web/src/lib/postgresReaders.ts` only (pre-existing pattern, never committed before this plan; no callsites changed)
- **Commit:** `b7b6aa2`

**3. [Rule 2 - Correctness] Plan action block said `fetchDashboardState` returns `{kv, updatedAtByKey, lastUpdated}`; Sheets twin returns `{kv, updatedAtByKey}`**
- **Found during:** Task 1 test scaffolding (reading sheets.ts:338-394 to confirm the exact shape)
- **Issue:** Plan 17 Task 1 behavior bullet #5 specified `fetchDashboardStateFromPostgres returns {kv, updatedAtByKey, lastUpdated}` — but the canonical Sheets-side `fetchDashboardState` returns only `{kv, updatedAtByKey}` (no `lastUpdated`). Shape parity is the cardinal invariant (D-E3) — drift here would break plan-19's 1-line branch.
- **Fix:** Implemented `fetchDashboardStateFromPostgres()` to return exactly `{kv, updatedAtByKey}` matching the Sheets twin. The corresponding test (Test 5) asserts on those two keys only. If a `lastUpdated` field is ever needed, it should be added to BOTH readers in the same plan — never one-sided.
- **Files modified:** test + implementation
