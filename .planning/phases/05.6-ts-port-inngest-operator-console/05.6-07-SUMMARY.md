## Decisions Made

- **service_role read path**: documented in the JSDoc on `manualOverrides.ts`. Anon could SELECT but cross-cuts with the eventual write path (plan 15 CRUD) — single-client keeps the trust boundary surface unified.
- **CAD-only return shape**: rather than returning `{spend, currency}` per platform and forcing the caller to convert (Apps Script pattern), the fetcher folds the conversion in. Plans 08-09 write the three CAD numbers directly to `data_daily.fb_spend_cad` / `ga_spend_cad` / `total_spend_cad` — schema matches.
- **`overridesApplied` observability flag**: not in the original .gs (Apps Script just logs to the execution log). Added so the Inngest `step.run` result can surface which days/platforms fired overrides — operator console jobs table will render this in plans 08-09 / 15.
- **Defensive platform guard**: CHECK constraint blocks at write, but a read-side console.warn catches any future constraint bypass (e.g., direct SQL inserts during data recovery). Silent skip rather than throw — one bad row shouldn't break the daily cron.
