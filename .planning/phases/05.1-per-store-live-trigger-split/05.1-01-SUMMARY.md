# Phase 5.1 Plan 01: Per-store live trigger split — Summary

**One-liner:** Split single runLiveUpdate trigger (19% failure rate) into 3 independent per-store triggers each with its own 6-min Apps Script budget, mirroring the Phase 5 daily-trigger fix.

## Objective

Close the gap discovered during Phase 5 UAT: the Triggers UI showed `runLiveUpdate` failing 19.12% of the time due to the same quota cascade that Phase 5 (05-01) fixed for the daily trigger. When all 3 stores run sequentially in one execution, one slow Shopify/Meta response can cascade into a 6-min cap timeout for the later stores. The fix is identical — each store gets its own execution context and its own budget.

### Main.gs (Task 2)

Replaced `installLiveTrigger` and `removeLiveTrigger`:

- `installLiveTrigger()` — installs 3 time-based triggers:
  - `runLiveUpdateUzoshop` @ everyMinutes(15)
  - `runLiveUpdateZolplus` @ everyMinutes(15)
  - `runLiveUpdateUsmile` @ everyMinutes(15)
  - No immediate execution on install (see decisions)
- `removeLiveTrigger()` — removes 4 handlers:
  - `runLiveUpdate` (legacy — pre-Phase-5.1)
  - `runLiveUpdateUzoshop`
  - `runLiveUpdateZolplus`
  - `runLiveUpdateUsmile`

All other Main.gs functions unchanged: `setupAll`, `setupCreateSheet`, `installDailyTrigger`, `removeDailyTrigger`, `onOpen`, `promptRunForDate_`, `promptBackfill_`, `showSpreadsheetUrl_`, `showVerifyConfig_`.
