# Phase 05.7 Plan: Cut-Over and Decommission Summary

Dashboard severed from Google Sheets at runtime; all `/api/*` routes read from
Supabase Postgres exclusively, `/api/dashboard-state` POST writes to the
`dashboard_state` JSONB table via service_role, and the clasp CI workflow is
deleted so .gs pushes no longer trigger Apps Script auto-deploys.

## Goal

The user said: **"I want to see data in the dashboard only from the DB."**
After this phase, the dashboard does **zero Sheets API calls at runtime**.
Apps Script triggers may continue running in parallel and writing to Sheets —
that's an operator-managed concern (documented in the manual), not a code
concern.

### Scope Decisions Deferred (Out of Scope by Design)

- `dashboard-web/src/lib/sheets.ts` and the 6 sister Sheets fetchers
  (products.ts, campaigns.ts, ads.ts, ordersAttribution.ts, productCatalog.ts,
  and the .ts fetchers under `lib/fetchers/`) **NOT deleted** even though
  they're no longer called from any route. They are kept as dead code because:
  1. Tree-shaking removes them from the production bundle automatically.
  2. `isAllowedStateKey` and `ALLOWED_STATE_KEYS` are still imported by
     `/api/dashboard-state` as the API-boundary validator — extracting them
     to a Sheets-independent module is a refactor outside this phase's scope.
  3. They provide a 10-minute emergency rollback path if 05.7 surfaces a
     critical Postgres bug.
- `dashboard-web/src/lib/featureFlags.ts` and its test file **NOT deleted**
  for the same rollback-safety-net reason. The function has zero callers.

## Operator Follow-Ups

Documented in User Manual §28.4. Summary:

1. **Disable Apps Script triggers** (recommended): visit
   `https://script.google.com/home`, open the ROAS Tracker project, click the
   clock (Triggers) icon, and delete each trigger. This stops Apps Script
   from continuing to consume daily Google quota writing to a spreadsheet
   the dashboard no longer reads.
2. **Smoke-test against PROD URL** (per the no-localhost memory): the
   manual lists exact `curl` commands to hit `roas-dashboard-smoky.vercel.app`
   and verify all `/api/*` routes return data + `/api/dashboard-state` POST
   succeeds + `/api/health` returns the hardcoded `sheets: 'ok'`.
3. **Optionally archive the spreadsheet** by making a copy named
   `ROAS-archive-pre-05-7-cutover` and freezing the original to view-only.
   Do **NOT** delete the `SPREADSHEET_ID` / `GOOGLE_CLIENT_EMAIL` /
   `GOOGLE_PRIVATE_KEY` Vercel env vars yet — they're the safety net for an
   emergency partial rollback.
