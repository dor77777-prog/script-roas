    **Plan-agent task.** Procedure:

    1. **Collect inline gaps from all raw-return JSONs:**
       Iterate over `.planning/phases/12-codebase-audit-baseline/raw-returns/*.json`. Each return has an inline field (per the scaffolding template): `test_coverage_gaps: [{file_line, what_is_untested, why_it_matters, suggested_fixture_sketch}, ...]`. Extract every entry.

    2. **Dedupe:**
       Two entries are duplicates if they share the same `file_line` AND `what_is_untested`. Merge — keep the strongest `why_it_matters` (prefer entries that cite production-shape impact per D-05).

    3. **Score and rank by operational risk:**
       - **verification-blocking** (score 9-10): untested behavior is the kind of bug a per-file audit can only suspect, not confirm (e.g. multi-step Inngest flows, cross-store edge cases, FX rounding at month boundaries). Top 5 entries get this label.
       - **high** (score 6-8): untested behavior that touches production data daily but degrades gracefully.
       - **medium** (score 3-5): untested behavior with rare triggers or limited blast radius.
       - **low** (score 1-2): cosmetic test gaps (e.g. missing test for a formatter edge case).

       Ranking heuristics:
       - Cite production-shape scenarios from D-05 (e.g. "uzoshop has X TikTok refreshes/day").
       - Weight Inngest cron paths high (write surface).
       - Weight algorithm files high (correctness surface).
       - Weight UI components lower (most logic lives in lib/).

    4. **Group by source file:**
       Final markdown has sections per file, gaps within each section listed in score order. Top-5 verification-blocking gaps are also called out in a "Top 5 (Verification-Blocking)" section at the top of the file.

    5. **Write `12-tests-needed.md`:**
       ```markdown
       # Phase 12: Test-Coverage Gaps (Ranked)

       **Generated:** {ISO-8601 UTC}
       **Total gaps:** {N}
       **Top-5 verification-blocking:** see section below

       ## Top 5 (Verification-Blocking)
       1. **{file}:{line} — {what}** (score {S}) — {why_it_matters} → fixture sketch: {sketch}
       2. ...
       3. ...
       4. ...
       5. ...

       ## Gaps by File

       ### dashboard-web/src/lib/{file}.ts ({N} gaps)
       #### Gap 1 ({label}, score {S})
       - **What's untested:** {what}
       - **Why it matters:** {why}
       - **Fixture sketch:** {sketch}
       - **File:line:** {file}:{line}

       #### Gap 2 ...

       ### dashboard-web/src/components/{file}.tsx ({N} gaps)
       ...
       ```

    6. Write using the Write tool — NEVER `cat << 'EOF'`.

    - Each gap has all 4 fields
