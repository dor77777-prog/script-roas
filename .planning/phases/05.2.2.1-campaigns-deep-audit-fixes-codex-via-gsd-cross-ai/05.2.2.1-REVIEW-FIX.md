### WR-04: parseDate accepts `'DD/MM/YYYY'` strings without validating real calendar dates

**Files modified:** `dashboard-web/src/lib/dateRange.ts`
**Commit:** `fc8bbc9`
**Applied fix:** Round-trip the candidate `${yyyy}-${mm}-${dd}` through `new Date(\`${candidate}T00:00:00Z\`)` and compare `d.toISOString().slice(0, 10)` to the candidate. JS Date rolls invalid days over (Feb 31 -> Mar 03), so a mismatch means the input was not a real calendar date — warn + return null. Aligns the legacy DMY fallback with the `isRealDate` gate that `parseRangeParams` already applies to query params.

### WR-05: getPreviousPeriod does not validate that range.from <= range.to before computing length

Inverted input ranges (e.g., from corrupted localStorage) no longer produce inverted output that silently returns empty downstream results.
