4-series (Meta + Google + Organic + Shopify) reconciliation with partial-order line-item attribution, dark-traffic indicator, and 4 Pearson correlations.

## What Was Built

**buildReconciliation** extended from 2-series (Meta, Shopify) to 4-series (Meta, Google, Organic, Shopify):

- **Google series**: walks all `campaignsData.rows` where `platform='Google'` and the campaign maps to any product in `mappedIds` via `productMap`; accumulates `conversionValue` per date
- **Organic series**: walks `ordersData.rows` for non-paid sources (direct, meta-organic, organic-search-engine, etc.); uses **partial-order line-item summation** — only mapped-product `revenueCad` is counted when an order contains mixed mapped/unmapped products
- **darkTrafficPercent**: `Math.round((1 - sumChannels/sumShopify) * 100)` when channels < 80% of Shopify actual
- **4 Pearson values**: `r` (Meta), `rGoogle`, `rOrganic`, `rCombined` (Meta+Google+Organic vs Shopify)
- Removed `platform !== 'Meta'` guard — Google campaigns now get a valid reconciliation panel

**Chart UI** updated with:
- 2 new `<Line>` components (Google: `#2563eb`, Organic: `#16a34a`)
- 4-entry legend
- Amber dark-traffic chip above chart when gap > 20%
- Pearson row shows all 4 values

**CampaignDrawer** updated:
- Added `useSWR` for `/api/campaigns` with same date-range key (SWR dedupes against `CampaignsTable`)
- Passes `campaignsData`, `ordersData` (`ordersAttrData`), and `productMap` state to `buildReconciliation`

## Deviations from Plan

**1. [Rule 2 - Missing functionality] Added campaignsData useSWR to CampaignDrawer**
- Found during: Task 2
- Issue: Plan said "campaignsData already available as useSWR result" but CampaignDrawer had no campaigns SWR — it only received filtered `rows` for the current campaign
- Fix: Added `useSWR<CampaignsResponse>` for `/api/campaigns` using `buildDateRangeKey`. SWR key matches CampaignsTable's key so no extra network round-trip (browser deduplication)
- Files: CampaignDrawer.tsx
- Commit: b081b5f

**2. [Rule 3 - Blocking issue] vi.mock() stubs for UI libraries in test file**
- Found during: Task 3
- Issue: Importing from `MetaShopifyReconciliation.tsx` in vitest (Node env) failed because `lucide-react` and `recharts` are not available in the test environment
- Fix: Added `vi.mock('lucide-react', ...)` and `vi.mock('recharts', ...)` stubs at the top of the test file — standard vitest pattern for testing pure functions exported from component files
- Files: buildReconciliation.test.ts
- Commit: 1fed446

**3. [Rule 3 - Blocking issue] node_modules symlink for worktree test execution**
- Found during: Task 3
- Issue: Worktree had an empty `node_modules` directory (only `.vite` cache); `npm test` couldn't find vitest/config
- Fix: Replaced empty directory with symlink to main project's `node_modules`; added `dashboard-web/node_modules` to `.gitignore`
- Commit: 1fed446

**4. Expanded organic sources set**
- Plan specified: `meta-organic, organic-search-engine, direct, meta-other, other`
- Actual: Added `other-referral` and `email` as well (consistent with `OrderSource` type union — all non-paid, non-google sources belong to "organic" bucket)
- Impact: Slightly broader organic attribution; better reflects true organic revenue
