### Step 5c writer logic (CBO vs ABO classification)

Per `MetaAds.gs:142-146` Hebrew docstring:

```text
CBO: campaign daily OR lifetime > 0   → campaign owns budget
ABO: campaign 0/null AND adset daily OR lifetime > 0
     → ad-set owns budget
'':  both 0/null (paused / lifetime-only handled elsewhere / unknown)
```

Lifetime fallback: when `daily_budget = 0`, we use `lifetime_budget` as the
"current commitment" surface. The dashboard column header says "Daily Budget"
but for lifetime-only campaigns showing the lifetime value is still more
useful than blank.

FX: `cadFor(rawILS, meta.budgets.currency)` — same closure that already
converts spend + conversion_value, so the FX rate is fetched ONCE per
(store, date) regardless of how many rows hit the column.

### Audit Finding #1 — FIXED (commit f3b160c)

`metaAdResult` test fixture in `cronDaily.test.ts` had stale field names from
before commit `98bbdb1` reshaped MetaAdRow:

```diff
- conversionValueCad: null,
- spendCad: null,
+ spend: 60,
```

the fixture means a future regression in that FX path WOULD now show up

### Why I did NOT also patch `cronLive.ts` (Shopify-only live trigger)

Per the cronLive.ts:11-21 docstring + D-C4 algorithm parity: the live trigger
intentionally refreshes ONLY Shopify (revenue + refunds within a 72h
cross-day window). Budgets are a `daily` concern — the cron-daily job at
00:05 Asia/Jerusalem picks them up once a day, which matches Apps Script's
`DailyUpdate.gs` exactly. Adding a per-15-min Meta budgets refresh would
4× the Meta API call budget without improving signal (Meta aggregates
budget values hourly upstream anyway).
