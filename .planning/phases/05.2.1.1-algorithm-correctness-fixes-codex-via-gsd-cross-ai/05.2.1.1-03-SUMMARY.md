## Decisions Made

1. **No @testing-library/react-hooks (TEST-04).** The hook is a `useMemo` wrapper around `analyzeAttributionForAdSet`. Testing the delegate directly catches the cross-store isolation bug we care about without adding a new devDependency for one test.
2. **Symmetric Rule 2 fix in `buildAnalysis` too.** The negative-metaClaim defect was identical in the shared engine used by ad-set/ad analyzers. Fixing only the campaign analyzer would leave the same false-positive trust signal in the granular drawers. The two fixes were committed together inside TEST-03.
3. **TEST-02 boundary value of 20, not 21.** Plan text said `round((1 - 0.799) * 100) = 21` but the rounded arithmetic is `Math.round(20.1) = 20`. The test pins the actual implementation; the plan's text was off by 1.
4. **Pure-TS mirror, not GAS-import.** Apps Script source cannot be loaded into the vitest runtime. TEST-06 introduces a TS mirror in `dashboard-web/src/lib/lineItems.ts` with a KEEP-IN-SYNC comment and a TODO to extract a shared schema in a future phase.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical input validation] Signed-input guard for `coverage` in attribution analyzers**
- **Found during:** TEST-03 (negative totalCad handling)
- **Issue:** Both `analyzeAttribution` (line 266-268) and `buildAnalysis` (line 764-766) computed coverage as `metaClaim > 0 ? Math.min(2, det/meta) : (det > 0 ? 1 : 0)`. With a negative `metaClaim` (malformed input — Meta never emits negative `conversion_value` in production, but a bad sheet edit could produce one), the fallback silently emitted `coverage = 1` ("perfect coverage") for any positive `det` — a false-positive trust signal. This was the latent issue TEST-03 was asked to pin.
- **Fix:** Added an explicit `metaClaim < 0 -> 0` branch so the function returns "undefined coverage" (0) instead of a false-positive 1. Symmetric across the campaign analyzer and the shared engine used by ad-set/ad analyzers.
- **Files modified:** `dashboard-web/src/lib/attributionAnalysis.ts`
- **Verification:** TEST-03 second case (`expect(result!.coverage).toBe(0)`) passes; existing tests still pass (verified all 40 analyzeAttribution* tests after the fix).
- **Committed in:** `921e127` (part of TEST-03 commit)

**2. [Rule 3 - Blocking] Exported `parseSource` from `ordersAttribution.ts`**
- **Found during:** TEST-01
- **Issue:** `parseSource` was an internal `function`, so the test file could not import it. The function is the writer-reader boundary the contract test needs to exercise.
- **Fix:** Added the `export` keyword.
- **Files modified:** `dashboard-web/src/lib/ordersAttribution.ts`
- **Verification:** `import { parseSource } from '@/lib/ordersAttribution'` resolves; TEST-01 runs.
- **Committed in:** `f4f8e65` (part of TEST-01 commit)
