# Phase 12.2 Plan 01: aiReport Polish — Wave 1 (P1) Summary

**One-liner:** Shipped 3 P1 aiReport.ts fixes (ALG-01 TikTok status taxonomy → `TIKTOK_ACTIVE_ENOUGH` symmetry; ALG-02 TikTok-inclusive budget allocation; ALG-07 raw coverage no upper clamp) as a composite commit with 10 RED-first regression tests, fully TDD-verified.

## ALG-01 — TikTok status taxonomy

- **Finding:** `aiReport.ts:1142` + `:1341` — both `isStatusOff` (Health Score) and `isOff` (Currently-Off) used a hard-coded allowlist (`norm !== 'ADGROUP_STATUS_DELIVERY_OK'`), silently mis-classifying TikTok BUDGET_EXCEED / AUDIT / REVIEWING / NOT_START campaigns as "off" and penalizing them -30 in Health Score.
- **Fix:** Replaced both predicates with `!TIKTOK_ACTIVE_ENOUGH.has(norm)` using the shared set from `lib/platformConfig.ts` (already used by `cronLive.isActiveForPlatform` + `postgresReaders` per AUDIT U-01 symmetry).
- **Source change:** added import at line 14; replaced lines 1142 + 1341 with audit-comment-annotated `!TIKTOK_ACTIVE_ENOUGH.has(norm)` predicate.
- **Test file:** `dashboard-web/src/lib/__tests__/aiReportTikTokStatus.test.ts` (4 tests):
  1. BUDGET_EXCEED → NOT listed in Currently-Off.
  2. DISABLE → IS listed (sanity).
  3. DELIVERY_OK → NOT listed (baseline).
  4. Health Score operator-adjustment differential: BUDGET_EXCEED no -30, DISABLE has -30.
- **TDD outcome:** RED 2/4 fail (BUDGET_EXCEED + health-penalty cases) → fix → GREEN 4/4 → revert-sanity 2/4 RED → restore GREEN. Verified.
- **Composite commit:** `db1212a` (covers all 3 fixes in this plan).

## ALG-02 — TikTok-inclusive budget allocation

- **Finding:** `aiReport.ts:2105` — `totalSpendAll = metaSpend + googleSpend` excluded TikTok entirely. TikTok-heavy stores (uzoshop with 60% TikTok mix) saw Meta 50% / Google 50% in the 'חלוקת תקציב לפי פלטפורמה' table, contradicting every other section (Top summary, per-platform CPM, TikTok deep-dive).
- **Fix:** Added `ttSpendBA` to the accumulator; recomputed `totalSpendAll = metaSpendBA + googleSpendBA + ttSpendBA`; emitted a TikTok row gated on `ttSpend > 0` mirroring the Top Summary conditional at line 240. Local accumulators renamed `metaSpendBA`/`googleSpendBA`/`ttSpendBA` to avoid shadowing the file-scope `ttSpend` from the Summary KPIs block (line 179) — a minimal-diff alternative to refactoring the duplicated loop.
- **Test file:** `dashboard-web/src/lib/__tests__/aiReportTikTokBudget.test.ts` (3 tests):
  1. Mixed-platform store (fb=100, ga=100, tt=300) → Meta 20% / Google 20% / TikTok 60% (was 50/50/—).
  2. TikTok row NOT emitted when `ttSpend === 0` across all days (gating preserved).
  3. Accumulator sums across multi-day rows (one day tt=0, another tt=200).
- **TDD outcome:** RED 2/3 fail → fix → GREEN 3/3 → revert-sanity 2/3 RED → restore GREEN. Verified.
- **Composite commit:** `db1212a`.

## ALG-07 — Coverage Math.min(1) clamp removed

- **Finding:** `aiReport.ts:1191` — `coverage = c.value > 0 ? Math.min(1, det / c.value) : ...` clamped halo cases (Shopify deterministic revenue exceeds platform claim — broken pixel / ad-blocker storm / ATT opt-out spike) to 1.0, stuck trustScore at the 100 ceiling, starving the U-05 halo-warning chip of its input.
- **Fix:** Replaced with `coverage = c.value > 0 ? det / c.value : det > 0 ? 1 : 0` — raw ratio, upper clamp removed. The `det > 0 ? 1 : 0` fallback for c.value=0 is preserved (Infinity-guard). Mirrors AUDIT U-05's `attributionAnalysis.computeCoverage` semantic (commit b846ae7).
- **Test file:** `dashboard-web/src/lib/__tests__/aiReportCoverageHalo.test.ts` (3 tests):
  1. Halo case (det=100, claim=50) yields HIGHER attributionClarity than baseline (det=50, claim=50) — pre-fix both clamped to 100.
  2. Normal under-report (det=50, claim=100) — coverage stays 0.5, attributionClarity < 100 (unchanged from pre-fix).
  3. Edge case (c.value=0, det=100) — coverage falls back to 1, no Infinity/NaN.
- **TDD outcome:** RED 1/3 fail (halo differential) → fix → GREEN 3/3 → revert-sanity 1/3 RED → restore GREEN. Verified.
- **Composite commit:** `db1212a`.
