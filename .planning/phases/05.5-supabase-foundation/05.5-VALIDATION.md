> Per-phase validation contract for feedback sampling during execution. Source of truth: `05.5-RESEARCH.md` §Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest (dashboard-web) + supabase CLI for DB-side checks + shell-based smoke tests |
| **Config file** | `dashboard-web/vitest.config.ts` (existing) |
| **Quick run command** | `cd dashboard-web && npm run test -- --run` |
| **Full suite command** | `cd dashboard-web && npm run test -- --run && npm run typecheck && supabase db diff` |
| **Estimated runtime** | ~30 seconds (vitest) + ~5 seconds (typecheck) + ~3 seconds (db diff) |

---

## Sampling Rate

- **After every task commit:** Run quick run command
- **After every plan wave:** Run full suite command
- **Before `/gsd-verify-work`:** Full suite must be green; production health-check curl returns `{ supabase: 'ok' }` against the cloud project (NOT localhost — per `feedback_no_localhost_checks.md`)
- **Max feedback latency:** 40 seconds
