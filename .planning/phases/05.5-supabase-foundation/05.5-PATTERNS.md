**Patterns to honor (combined from RESEARCH.md §Standard Stack + §State of the Art + Anti-Patterns):**
- `TEXT` (not `VARCHAR(N)`) for all string cols — Postgres community convention.
- `NUMERIC(14, 4)` for all monetary cols (CAD spend, revenue, COGS) — exact precision; avoids float-error accumulation.
- `TIMESTAMPTZ` for all audit cols (`updated_at`, `created_at`) — Supabase is UTC by default.
- `JSONB` for `dashboard_state.value` (7 keys, all different shapes) and `orders_attribution.line_items`.
- `TEXT` (not `BIGINT`) for `product_id` — Shopify uses 17-19 digit numerics that overflow JS `Number` precision (see `SheetBuilder.gs:1163-1168` for the inline warning).
- Composite PKs follow the unified-per-entity pattern: `(date, store_id, ...)` for daily tables; `(store_id, order_id|product_id)` for entity tables.
- `CREATE INDEX idx_{table}_store_date ON {table} (store_id, date)` on every daily table for dashboard cross-store queries.
- File header MUST contain:
  ```sql
  -- supabase/migrations/{timestamp}_initial_schema.sql
  -- Phase 05.5 — 10-table schema mirroring Sheets 1:1 (D-A2)
  -- RLS deliberately NOT enabled — single-user URL-obscurity (per /gsd-explore 2026-05-21)
  -- ADDITIVE
  ```
- Each `CREATE TABLE` followed by `COMMENT ON TABLE` referencing the D-A5 row number.
- Migration discipline header (per RESEARCH.md §Code Examples Example 5):
  ```sql
  -- ⚠️ Migration discipline:
  --   - Never edit this file after `supabase db push` succeeds.
  --   - Write a follow-up migration if changes are needed.
  --   - DESTRUCTIVE operations require a `-- DESTRUCTIVE: <reason>` first line.
  ```

```ts
import { NextResponse } from 'next/server';
import { supabase } from '@/lib/supabase';
import { getAuth } from '@/lib/sheets';
import { google } from 'googleapis';

export const revalidate = 10;

type HealthStatus = 'ok' | 'down';
type HealthResponse = {
  sheets: HealthStatus;
  supabase: HealthStatus;
  lastChecked: string;
  errors?: { sheets?: string; supabase?: string };
};

async function pingSheets(): Promise<void> {
  const auth = getAuth();
  const sheets = google.sheets({ version: 'v4', auth });
  await sheets.spreadsheets.get({
    spreadsheetId: process.env.SPREADSHEET_ID!,
    fields: 'spreadsheetId',
  });
}

async function pingSupabase(): Promise<void> {
  const { error } = await supabase
    .from('stores')
    .select('id', { count: 'exact', head: true });
  if (error) throw new Error(error.message);
}

export async function GET() {
  const [sheetsRes, supabaseRes] = await Promise.allSettled([
    pingSheets(),
    pingSupabase(),
  ]);

  const errors: HealthResponse['errors'] = {};
  const sheetsStatus: HealthStatus = sheetsRes.status === 'fulfilled' ? 'ok' : 'down';
  const supabaseStatus: HealthStatus = supabaseRes.status === 'fulfilled' ? 'ok' : 'down';
  ...
}
```

**Patterns to honor:**
- `export const revalidate = 10` matches existing `dashboard-state` cadence; no `force-dynamic` (Anti-Pattern — conflicts with explicit `Cache-Control` per RESEARCH.md Anti-Patterns).
- BUT: RESEARCH.md hardcodes `Cache-Control: s-maxage=10, stale-while-revalidate=60` in the response (line 412) — this differs from the project pattern of `cacheControl(key)` from `cacheConfig.ts`. **Planner discretion:** either (a) extend `CACHE_CONFIG` in `lib/cacheConfig.ts` with a `health: { revalidate: 10, swr: 60 }` entry and call `cacheControl('health')` (matches existing convention), or (b) hardcode (matches RESEARCH.md skeleton). Recommend (a) for codebase consistency.
- `Promise.allSettled` (per RESEARCH.md §Pattern 5) — both checks complete; one failure doesn't abort the other.
- `pingSheets()` calls `sheets.spreadsheets.get` (metadata only, ~1 quota unit per call per RESEARCH.md Pitfall 7) — NOT `values.get`.
- `pingSupabase()` uses `{ count: 'exact', head: true }` — zero row data transferred (per RESEARCH.md Anti-Patterns: never `select('*')` for the ping).
- Error sanitization: per RESEARCH.md `errors.sheets = String(sheetsRes.reason?.message ?? sheetsRes.reason)`. **Discretion call:** could route through `userFacingError()` for consistency with sibling routes; RESEARCH.md doesn't do this — recommend going through `userFacingError()` to keep sanitization centralized.
- Always returns HTTP 200 (matches sibling soft-fail routes) with shape `{ sheets, supabase, lastChecked }` even if both checks fail — the SyncIndicator parses the JSON to decide red/yellow/green.

```ts
  try {
    const data = await /* fetch */;
    return NextResponse.json(
      { /* shape */, lastUpdated: new Date().toISOString() },
```
