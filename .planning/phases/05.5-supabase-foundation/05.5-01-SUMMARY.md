- **Reused pre-existing Supabase project** — `script-roas` (ref `npegxufdupooqovrewyb`) already exists in operator's account in Central EU Frankfurt. It matches every Task 0 parameter (Free tier, EU region, operator-accessible via `supabase projects list`). - **`project_id` set manually to cloud ref** — `supabase init` defaulted `project_id` to the worktree directory name (`agent-a78aaf89fd8e424a1`), which contains hyphens and would fail the plan's verify regex `^project_id[[:space:]]*=[[:space:]]*"[a-z0-9]+"`. `supabase link --project-ref` on CLI 2.98.1 does NOT update `config.toml` (it writes only to `supabase/.temp/project-ref`). The plan's "Studio shows 10 tables / 3 rows / 2 rows" is a redundant trust-but-verify check. Used REST API (`/rest/v1/{table}?select=*`) with the project's anon key — which queries the SAME data Studio displays — to verify HTTP 200 on all 10 tables, stores returns 3 rows with correct meta_ad_account_id values, and notification_config returns 2 rows with the correct provider/active pairs.
