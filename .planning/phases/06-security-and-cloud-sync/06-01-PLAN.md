```typescript
/**
 * Resolves Google Sheets credentials based on mode (per Phase 6 SEC-01).
 *
 * Three env var pairs supported, with fallback semantics:
 *  - mode='read'  → tries GOOGLE_READER_EMAIL + GOOGLE_READER_KEY first,
 *                   falls back to GOOGLE_CLIENT_EMAIL + GOOGLE_PRIVATE_KEY.
 *                   Scope: spreadsheets.readonly.
 *  - mode='write' → tries GOOGLE_WRITER_EMAIL + GOOGLE_WRITER_KEY first,
 *                   falls back to GOOGLE_CLIENT_EMAIL + GOOGLE_PRIVATE_KEY.
 *                   Scope: spreadsheets.
 *
 * The fallback exists so a Vercel deploy without the new env vars set still
 * works on the legacy single-SA credentials (no downtime during operator
 * rotation). Throws only when BOTH the mode-specific pair AND the legacy
 * pair are unset (i.e., no credentials available at all).
 *
 * Threat refs: T-06-01-01 (split blast radius), T-06-01-02 (fallback risk —
 * accepted until operator completes rotation, see SETUP.md).
 */
function getAuth(mode: 'read' | 'write' = 'read'): google.auth.GoogleAuth {
  // Resolve credentials with mode-specific primary + legacy fallback.
  const primaryEmail =
    mode === 'write' ? process.env.GOOGLE_WRITER_EMAIL : process.env.GOOGLE_READER_EMAIL;
  const primaryKey =
    mode === 'write' ? process.env.GOOGLE_WRITER_KEY : process.env.GOOGLE_READER_KEY;

  const fallbackEmail = process.env.GOOGLE_CLIENT_EMAIL;
  const fallbackKey = process.env.GOOGLE_PRIVATE_KEY;

  const clientEmail = primaryEmail || fallbackEmail;
  const privateKeyRaw = primaryKey || fallbackKey;

  if (!clientEmail || !privateKeyRaw) {
    throw new Error(
      `Missing Google credentials for mode='${mode}'. Set ` +
        (mode === 'write'
          ? 'GOOGLE_WRITER_EMAIL + GOOGLE_WRITER_KEY '
          : 'GOOGLE_READER_EMAIL + GOOGLE_READER_KEY ') +
        'or the legacy GOOGLE_CLIENT_EMAIL + GOOGLE_PRIVATE_KEY pair. ' +
        'See dashboard-web/.env.example + SETUP.md for setup.',
    );
  }

  // Vercel-style private keys escape newlines as \n strings; normalize.
  const privateKey = privateKeyRaw.replace(/\\n/g, '\n');

  // Reader scope is readonly — leaking the reader SA key cannot mutate data.
  // Writer scope is full spreadsheets — used only by upsertDashboardStateKey
  // and (Phase 6 plan 03) appendAuditRow.
  const scope =
    mode === 'write'
      ? 'https://www.googleapis.com/auth/spreadsheets'
      : 'https://www.googleapis.com/auth/spreadsheets.readonly';

  return new google.auth.GoogleAuth({
    credentials: { client_email: clientEmail, private_key: privateKey },
    scopes: [scope],
  });
}
```

## Service-account split (Phase 6, May 2026)

To reduce blast radius if a Google SA credential leaks, the dashboard uses two
service accounts:

| SA | Scope | Used by | Vercel env vars |
|----|-------|---------|-----------------|
| Reader | `spreadsheets.readonly` | All GET routes (`/api/data`, `/api/campaigns`, `/api/products`, `/api/orders-attribution`, `/api/dashboard-state` GET, `/api/store-meta`) | `GOOGLE_READER_EMAIL`, `GOOGLE_READER_KEY` |

### Operator runbook (one-time setup)

1. **Create the writer SA in Google Cloud Console**:
   - IAM & Admin → Service Accounts → Create Service Account.
   - Name: `roas-dashboard-writer`.
   - No roles needed at the project level (we authorize via spreadsheet sharing).
   - After creation: Keys tab → Add Key → Create new key → JSON.
   - Open the JSON file, copy `client_email` and `private_key` (the multi-line
     `-----BEGIN PRIVATE KEY-----` block).

   - Open the production spreadsheet in Google Sheets.
   - Right-click the `dashboard-state` tab → Protect sheet → Set permissions →
     Restrict who can edit → add the writer SA's email as Editor.
   - Repeat for the `dashboard-state-audit` tab (it will be auto-created on
     the first POST after Phase 6 ships; you may need to come back and share
     it after the first audit append).
   - Workbook-level Editor is acceptable as a coarser fallback, but tab-level

   - Share dialog → change the existing SA from Editor to Viewer at the

mutation possible).
