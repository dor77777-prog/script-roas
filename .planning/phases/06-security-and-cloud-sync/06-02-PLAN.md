<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser tab → Vercel CDN/Edge | The polling rate determines how many edge invocations the dashboard generates per user per session. Lower = less quota burn, less data-staleness risk if the dashboard becomes multi-user later. |
| User input event → polling resume | The `idle-stop` flag is conservative — any mouse / key / touch event lifts the freeze. We don't want a stale UI when the user comes back; we DO want it stale while they're away. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Denial of Service | `/api/dashboard-state` (Sheets read quota in long-tail open tabs) | mitigate | Adaptive polling caps long-tail load: a tab left open overnight idles out at 0 calls/hour after the 10min mark, then the next focus resumes. Net effect: ~10x reduction in background load versus the current fixed 30s loop. |
| T-06-02-02 | Information Disclosure | None for this plan — polling rate doesn't expose new data. | accept | (No mitigation needed; included for completeness.) |
| T-06-02-03 | Tampering | SSR-rendering CloudSync would access `window` before mount → crash | mitigate | `'use client'` directive + `typeof window === 'undefined'` guards inside the hook's effect ensure SSR is a no-op. CloudSync.tsx already has `'use client'` — we preserve it. |
| T-06-02-04 | Repudiation | Idle detection doesn't include scroll events | accept | Scroll events fire less reliably than mouse/key/touch (scroll-snap, momentum scrolling, etc.). The three primary inputs (mousemove/keydown/touchstart) are the canonical "user is engaged" signals. Visibility events catch tab-switches. The gap (user scrolls the page without moving the mouse) is acceptable: scroll-only-no-movement is rare and visibility/focus events still catch tab-back-from-other-window. |

```typescript
'use client';
import { useEffect, useRef, useState } from 'react';

/**
 * Polling-cadence constants (Phase 6 plan 02).
 * - VISIBLE_MS: tab is in foreground; user is likely watching.
 * - HIDDEN_MS: tab is backgrounded but the user hasn't gone idle.
 * - IDLE_THRESHOLD_MS: no input events for this long → stop polling
 *   entirely until the user comes back (focus or any activity event).
 *
 * Tuned for single-user internal dashboard: HIDDEN_MS = 5min is generous
 * enough that ad-spend / orders edits feel fresh when the user tabs back,
 * but slow enough to cut background quota burn by ~10x vs. the prior
 * fixed-30s loop.
 */
const VISIBLE_MS = 30_000;
const HIDDEN_MS = 300_000;
const IDLE_THRESHOLD_MS = 10 * 60 * 1000;

export type AdaptivePollingMode = 'visible' | 'hidden' | 'idle-stop';

/**
 * Adaptive polling driver. Calls `onTick` at a cadence determined by:
 *   - `document.visibilityState === 'visible'` → every VISIBLE_MS (30s)
 *   - `document.visibilityState === 'hidden'`  → every HIDDEN_MS (5min)
 *   - No `mousemove`/`keydown`/`touchstart` events for > IDLE_THRESHOLD_MS
 *     (10min) → STOP polling. Resumes on next focus or activity event.
 *
 * Returns the current `mode` (mainly useful for diagnostics in dev). The
 * ref-based `tickRef` keeps the latest `onTick` reachable without
 * re-arming the timer on every render — this matters because CloudSync
 * is mounted once at the dashboard root and its parent might re-render
 * frequently (e.g. on tab switches).
 *
 * SSR safety: every DOM/window access is gated by `typeof window` checks.
 * On the server, the effect's body is a no-op and the return mode stays
 * 'visible' (the initial state) — meaningless on the server but harmless.
 *
 * Cleanup: removes the timer + all 5 event listeners on unmount. No
 * memory leak even when CloudSync is mounted/unmounted in test harnesses.
 */
export function useAdaptivePolling(onTick: () => void): AdaptivePollingMode {
  const [mode, setMode] = useState<AdaptivePollingMode>('visible');
  const tickRef = useRef(onTick);
  const lastActivityRef = useRef<number>(Date.now());
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  // Always keep the latest onTick reachable without re-arming the effect.
  useEffect(() => {
    tickRef.current = onTick;
  });

  useEffect(() => {
    if (typeof window === 'undefined') return;

    const markActivity = () => {
      lastActivityRef.current = Date.now();
      // If we'd stopped due to idle, kick polling back on at the appropriate
      // rate for the current visibility state.
      setMode(prev => {
        if (prev !== 'idle-stop') return prev;
        return document.visibilityState === 'visible' ? 'visible' : 'hidden';
      });
    };

    const computeMode = (): AdaptivePollingMode => {
      const idleFor = Date.now() - lastActivityRef.current;
      if (idleFor > IDLE_THRESHOLD_MS) return 'idle-stop';
      return document.visibilityState === 'visible' ? 'visible' : 'hidden';
    };

    const arm = () => {
      if (timerRef.current) {
        clearTimeout(timerRef.current);
        timerRef.current = null;
      }
      const m = computeMode();
      setMode(m);
      if (m === 'idle-stop') return; // no timer; rearm on next activity/focus
      const delay = m === 'visible' ? VISIBLE_MS : HIDDEN_MS;
      timerRef.current = setTimeout(() => {
        tickRef.current();
        arm();
      }, delay);
    };

    const onVis = () => arm();
    const onFocus = () => {
      markActivity();
      arm();
    };

    document.addEventListener('visibilitychange', onVis);
    window.addEventListener('focus', onFocus);
    window.addEventListener('mousemove', markActivity, { passive: true });
    window.addEventListener('keydown', markActivity);
    window.addEventListener('touchstart', markActivity, { passive: true });

    arm(); // schedule the first tick

    return () => {
      if (timerRef.current) clearTimeout(timerRef.current);
      document.removeEventListener('visibilitychange', onVis);
      window.removeEventListener('focus', onFocus);
      window.removeEventListener('mousemove', markActivity);
      window.removeEventListener('keydown', markActivity);
      window.removeEventListener('touchstart', markActivity);
    };
  }, []);

  return mode;
}
```

```typescript
'use client';

import { useEffect } from 'react';
import { hydrateFromCloud } from '@/lib/cloudSync';
import { useAdaptivePolling } from '@/lib/useAdaptivePolling';

/**
 * Mounts the cloud-sync hydrate cycle. On mount we fire once immediately so
 * the dashboard reflects cloud state ASAP, then `useAdaptivePolling` takes
 * over the recurring cadence:
 *   - visible tab → 30s
 *   - hidden tab  → 5min
 *   - idle > 10min → stop until activity resumes
 *
 * This replaces the old fixed-30s `setInterval` loop (Phase 6 plan 02).
 */
export function CloudSync() {
  useEffect(() => {
    // Initial hydrate on mount — runs once independent of the polling hook,
    // so the dashboard has cloud state immediately even before the first
    // adaptive-poll fires.
    void hydrateFromCloud();
  }, []);

  useAdaptivePolling(() => {
    void hydrateFromCloud();
  });

  return null;
}
```
